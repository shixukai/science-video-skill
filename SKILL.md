# Science Video Production

Start from a concrete question and make its answer visible. Prioritize the opening before polishing the rest: find an understandable event worth watching, compare genuinely different ways to reveal it, and test the chosen opening in the existing sample review. “80% on the opening” means creative attention and selection effort, not a word-count, timer, generation quota or platform-algorithm weight. Necessary science, body explanation and delivery checks remain intact.

Choose the commissioned [production route](references/tool-routing.md#lock-the-primary-tool-by-final-film-style). Across routes, prefer continuous whole-script Mandarin narration using local IndexTTS-2.5 voice clone (`scripts/synthesize_indextts2.py` + `scripts/prepare_voice_master.py --polish`, `mandarin-indextts25-clone-polished-v1`), paired with [Edge cloud narration](references/voice-reference.md#one-narration-master-and-one-shared-processing-chain) via [synthesize_edge_tts.py](scripts/synthesize_edge_tts.py) for English (`en-US-AndrewMultilingualNeural` `+4%`) and cloud Mandarin fallback (`zh-CN-YunxiNeural` `+4%`). Read [Google Flow production](references/google-flow-production.md) for its bilingual shared-picture workflow, whole-track mastering and scoped FFmpeg composition; this is not permission for substitute imagery or arbitrary gap-filling. Local realism uses MoneyPrinterTurbo; controlled 3D uses Blender or `vork` according to mechanism and asset fit. Topic category alone does not select a route.

## Opening-first work order

1. Read the [opening workbench](references/viral-appeal-and-packaging.md#win-the-first-two-seconds): visible material → genuinely different candidates → strongest alternative comparison → picture, natural first line and sound together. Keep source, rights, production feasibility and the first body payoff connected.
2. Use the existing G1 hook record and 0–5 s sample. At 2 s observe object/event recognition and a reason to continue; the natural payload may finish by the configured 3.5 s / 20 spoken-unit ceiling, and a concrete [viewing promise](references/viral-appeal-and-packaging.md#lock-a-concrete-viewing-promise-by-about-8-seconds) follows by about 8 s. Actual normally paced audio decides duration, not a count. See the [beat sheet](references/viral-appeal-and-packaging.md#the-opening-beat-sheet).
3. Reuse an independent internal first-view normal-speed actual watch/listen for the [sample/final hook review](references/viral-appeal-and-packaging.md#produce-and-test-the-hook-first), then complete the [body and opening-to-body handoff](references/viewer-retention-design.md#connect-the-opening-to-the-first-body-observation). No live audience recruitment or platform performance is needed for production review. Do not manufacture fresh reviewers or repeat forms to simulate progress.
4. Carry viewers to the end with the [open-loop ledger](references/viral-appeal-and-packaging.md#keep-one-question-open-until-the-final-answer) in `payoff_steps`: the main question stays open until a late final answer, each section opens its next concrete question before closing the current one, and the film [ends soon after the answer](references/viral-appeal-and-packaging.md#end-fast-and-invite-real-interaction). Locate risks on actual cuts with `retention_timeline.py`; it is a locator, not a gate.
5. Read other responsibilities only when needed below. Simplify repeated setup, narration and procedures, not prerequisites, scientific meaning, rights, 1080p or actual audiovisual acceptance.

## Scope and instruction priority

Follow host instructions, tools and permissions, then the user's current explicit request and still-valid authorization. New requests supersede conflicting older preferences; do not ask again for existing authorization. Responsibility bodies own rules, configuration owns defaults, and episode records own current scope and evidence. Templates, examples and indexes create no additional gates.

For multi-dimensional improvement, fix the observed decision failure rather than adding generic quality slogans: preserve [conditional claim meaning](references/science-and-rights.md#preserve-claim-meaning-through-production-handoffs), diagnose [competing attention](references/viewer-retention-design.md#diagnose-competing-attention-before-making-the-edit-faster), and verify [role handoffs](references/subagent-orchestration.md#accept-handoffs-by-meaning-not-only-by-file-presence). These are targeted uses of existing stages, not extra approval gates.

Maintain production instructions, normative references, template guidance and subagent definitions in English. Use each audience version's language for narration, captions and copy. Preserve actual approved model-input payloads, source quotations, proper names and language-sensitive test fixtures. Documentation language does not change the audience language or authorize resynthesis, rendering or publication.

If the production route and visual style are unspecified, use the series' local realistic default. An explicit controlled 3D choice routes to Blender or `vork` unless the user specifies an engine. Mixed styles and cloud generation follow their commissioned scope. Historical 2D applies only to specifically authorized 2D work or independent covers. Preserve a user-selected topic and design its explanation for the intended audience.

### Direct publication of a user-specified finished file

When the user explicitly requests publication of an existing, identified video, carry out the authorized actions for that account, version and destinations under the [manual-click and review handoff rule](references/production-checkpoints.md#manual-clicks-and-publication-review-handoff). G1–G6 production records, `publish_ready`, and new production QA are unnecessary for this direct route. Record known concerns and missing reviews accurately. Preserve applicable production gates on production and repair commissions. Reuse still-valid approval when the host and tool permit it. Required action-time confirmations, agreements, handoffs and platform restrictions still apply. Check existing records for duplicate submissions and prepare the specified cover, eligible settings and declarations before submission. Report the actual submission action or user handoff. After the user confirms publication of the exact version, follow the [archive handoff](references/production-checkpoints.md#move-accepted-and-published-videos).

Reuse a matching existing lock instead of generating one for every operation. `plan` does not advance a gate; G1–G7 check the applicable evidence. `delivery` checks local completion through G5, `publish_ready` through G6, and `covers` only covers.
