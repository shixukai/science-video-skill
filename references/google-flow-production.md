# Google Flow cloud production

## Select the route and budget bilingual chains at G1

Set `design.production_route=google_flow` when the user commissions a Google Flow production. Generate all delivered video imagery and physical foley (`1080p Upscaled`, `24/1 fps` CFR) in [Google Flow](https://flow.google.com/), synthesize **Chinese (`zh`) narration continuously as one whole-script pass using the series default Microsoft Edge cloud neural voice `edge-tts` (`zh-CN-YunxiNeural`, `rate="+4%"` via `scripts/synthesize_edge_tts.py`)** (and synthesize paired English `en` narration continuously via `edge-tts` `en-US-AndrewMultilingualNeural` `+4%`, or Google AI Studio Gemini TTS / native Flow `Veo 3.1` speech when explicitly selected), then master the continuous voiceover (`prepare_voice_master.py`) and composite/mux (`ffmpeg`) it cleanly with the `1080p` Google Flow visuals, ducked Flow foley/ambience, and synchronized captions. Local TTS (`Qwen3-TTS`, OS TTS, `synthesize_voice.py`), local 3D rendering (`Blender`/`vork`), screen capture, `MoneyPrinterTurbo`, and stock footage/music cannot supply delivered media on this route.

Plan complete explanatory chains before writing prompts:

- **Plan the full explanation first.** Trace the [causal chain](topic-contract.md#complete-chains-and-duration-for-engineering-and-manufacturing-topics) from the initial conditions and trigger through each necessary physical change to the result and its evidence. Include a comparison, failure case or operating limit when it helps explain why the result occurs. In the existing shot table, map each key link to what viewers see, what the narration explains and the time they need to observe it. For an invisible mechanism, show a scientifically valid observable effect or a clearly identified model, and maintain one persistent subject and spatial orientation across `2–4` consecutive shots (bridged via Flow `Frames`/`Extend` or a shared scene preamble) for multi-step physical or physiological deformations instead of swapping to an unrelated prop every `~5 s`.
- **Let the mechanism set chapter depth and length (never 1 clip per stage).** Set the number of chapters, chained shots, and total runtime from the complete explanation, natural narration, and observation time in both languages. Do not treat `8 s` Veo clips as 1-clip-per-idea flashcards: for multi-stage mechanisms (`>= 4` required scope items), build `3–5` sustained chapters (`30–60 s` and `4–7` chained `8 s` shots per chapter via `>> Extend` or saved tail-frame `Frames`, totaling `>= 450–900+` CJK chars / `>= 280–580+` English words and `>= 135–270 s` runtime, screened by `compressed_checklist_episode` in `google_flow_audit.py`). Never ping-pong exterior live shots and interior `not_observable` cutaways on isolated single shots (`world_ping_pong_cuts`), and place any boundary condition or counterexample inside the chapter whose variable it tests rather than tacking it onto the end with a semicolon. If available credits or a verified Flow limit cannot accommodate the complete version, report the constraint cleanly and keep the full explanation intact.
- **Bilingual pairing at G1.** Every complete Google Flow film delivers two individually playable sibling records under the same project: `episode.zh.json` (Chinese narration and captions) and `episode.en.json` (English narration and captions), sharing the same scientific picture sequence, shot order, truth register, `time_scale` annotations, and common foley/ambience/music stems.
- **Native 24 fps clip budgeting before generation.** Flow's native output stream runs at Constant Frame Rate `24/1 fps` (`~7.917 s` / `190` frames in `720p Original`; `~7.833 s` / `188` frames in `1080p Upscaled`). After trimming `0.15–0.40 s` of ramp/conditioning head and holding a `0.20–0.40 s` tail margin before drift, each raw clip yields roughly `6.8–7.4 s` of usable core. Budget every shot against `max(span_zh, span_en)` at G1: if either language exceeds `~7.0 s` on a shot (or needs longer observation), split that beat into adjacent sub-shots (`SHxxA`/`SHxxB`), generate a Flow `Extend` continuation, or bridge with tail-to-head `Frames` conditioning before final rendering. Never stretch raw clips with `setpts` slow motion, freeze tails with `tpad`, loop clips, or apply `atempo` warping to fill narration overrun.
- **Lock `design.output.fps=24` for pure Flow timelines.** Keep timeline composition and final encoding at native `24/1 fps` CFR (`1920×1080` default landscape or `1080×1920` when vertical is explicitly commissioned; honor higher explicit targets) so 24 fps Flow clips are never judder-converted to `30 fps` by frame duplication. Use non-24 rates only when an explicit higher-rate deliverable is commissioned and backed by documented frame-rate handling.
- **Mechanism and scope boundaries.** At G1, verify whether generated shots can preserve required geometry, scale, state order and continuity without turning invisible fields into photoreal objects. Apply [full-frame scope rules](realistic-production.md#declaration-structure-and-validation-scope) if changing the visual medium, report route blockers cleanly without silently switching routes, and follow [science and provenance](science-and-rights.md).

## Start with active project controls, pacing and 1080p Upscaled staging

Before generating shots, open or create the authorized Flow project in **explicit desktop viewport (`>= 1440×900`, enforced at the start of every browser step and after every navigation—below `~840 px` width Flow falls back to `container mobile` and hides `Scenes`, `+ Add clip`, and `>> Extend`)** and verify current account/region access, active model matrix (`Veo 3.1 - Fast` `720p` base at `10` credits/8s, `Veo 3.1 - Quality` at `100` credits/8s, `Omni 1.2 Flash` at `24` credits/8s; in-editor `>> Extend` automatically switches to `Omni 1.2 Flash` fixed `+4 s` at `12` credits and disables `1080p Upscaled`), input modes (`Text`, `Frames`, `Ingredients`), aspect ratio, duration option (`4s`/`6s`/`8s`), single-clip `1080p Upscaled` (`0` credits) vs extended/multi-clip `Download scene` (`1280×720` cloud output), generated audio behavior, and quoted credit balance. Leave room for the `>= 0.15 s` opening hook trim. [Get started with Flow](https://support.google.com/flow/answer/16353333?hl=en&co=GENIE.Platform%3DDesktop), [Create videos](https://support.google.com/flow/answer/16353334?hl=en&co=GENIE.Platform%3DDesktop), [Models and supported features](https://support.google.com/flow/answer/16352836?hl=en), [Regions](https://support.google.com/flow/answer/16353544?hl=en), [Credits](https://support.google.com/flow/answer/16526234?hl=en).

- **Disk-backed prompt ledger and compaction recovery.** Before submitting any browser batch, save a versioned local ledger mapping every `shot_id` to its exact verbatim prompt, input mode, conditioning source (`Frames`/`Ingredients`), expected usable span, Flow project card/candidate index, and downloaded filename. Always re-read that disk ledger after any context compaction or session resume so shot prompts and card indices never drift.
- **Strict serial submission and anti-bot restraint.** Submit and upscale **one prompt/card serially** at calm, human-paced intervals, awaiting generation and upscale completion cleanly before starting the next request. Never burst concurrent browser tabs or rapid-fire loops. If Flow displays an anti-bot challenge (`"We noticed some unusual activity"`), CAPTCHA, sign-in barrier, regional block, or credit exhaustion, stop immediately, record the exact blocker and checkpointed card index, and ask the user; never attempt to wait out, click through, script around, or bypass any gate.
- **Reuse clean in-project assets.** Prefer existing clean project cards, saved `Frames` and verified `Ingredients` over duplicate re-uploads or blind re-rolls. Submit only the minimum authorized visual input needed, avoiding unnecessary confidential or identifiable media. [Minimal media transfer](tool-routing.md#review-media-without-repeated-uploads), [Flow data controls](https://support.google.com/flow/answer/17025472?hl=en), [Flow privacy notice](https://labs.google/fx/tools/flow/privacy).
- **Mandatory `1080p Upscaled` download and staging verification.** Trigger Flow's `1080p Upscaled` export for every selected shot (`720p Original` may guide candidate selection only and never enters final sample/episode assembly when HD output is required). Verify every Playwright/browser download completes cleanly (`dl.path() !== null` and `dl.failure() === null`), save to deterministic shot filenames, and run `ffprobe` on arrival to confirm actual width/height (`>= 1920×1080` for default 16:9), `24/1 fps` stream rate, playable video + `48 kHz` audio stream integrity, and clean frame count. Generate both a raw contact sheet (`0 s`, `2 s`, `4 s`, `6 s`, `7.5 s` / head-mid-tail) and **full-resolution `1920×1080` hero/frame-0 stills** before post-production assembly so defects or body-horror artifacts never hide until G5.

## Prompting, conditioning, clean phantoms and native foley

Write every shot from its [shot card](realistic-direction.md#write-a-shot-card-before-the-prompt) first: fix the shot's [truth register](realistic-direction.md#assign-a-truth-register-to-every-shot), declared [time scale](realistic-direction.md#declare-and-verify-time-scale), scene lighting preamble, fixed camera package, and single starting-to-resulting physical transition described in [concrete physical language](realistic-direction.md#word-prompts-physically). Select candidates [science first](realistic-direction.md#generate-and-select-in-the-right-order), then continuity, phone-screen readability, optical texture and aesthetic polish.

1. **Hook sample (`0–5 s`) and G3 precede full body expansion.** Produce `SH01` (and any seamless hook join) at `1080p Upscaled` first. Trim at least the first `0.15 s` (`>= 4` frames) of any static conditioning settle so motion begins on frame 0 under [the two-second hook rule](viral-appeal-and-packaging.md#win-the-first-two-seconds) and reaches a clear visual change by `~2.0 s`. Inspect opening Frame 0 and key hook frames at **full `1920×1080` resolution** per [viewing-safety imagery rules](visual-system.md#handle-potentially-disturbing-imagery) before running the cold hook test. Assemble both the primary Chinese `0–5 s` hook sample and the English `0–5 s` opening check against the identical visual beats, measure with `scripts/opening_hook.py` and pass [the hook test](viral-appeal-and-packaging.md#produce-and-test-the-hook-first) + representative risk-relationship G3 before generating remaining body shots.
2. **Frameless, text-free physical staging (`>= 90%` safe zone).** Instruct clean, unlabeled, unmarked physical props, ungraduated instrument housings, or unreadable background displays per [honest instruments](realistic-direction.md#keep-numbers-instruments-and-readable-surfaces-honest) and [marking limits](visual-system.md#in-picture-markings-require-specific-consent). Never prompt for multi-digit numeric counters, on-screen labels, split-screen panels, picture-in-picture insets, decorative borders, vignette frames or UI mockups — Flow renders pseudo-glyphs and clipped overlays that break close-ups. Compose key action inside the central/upper-middle safe area (`~90%` margin clear of platform UI chrome).
3. **Clean biological cutaways vs. non-biological benchtop phantoms.** Per [viewing-safety imagery rules](visual-system.md#handle-potentially-disturbing-imagery), NEVER prompt or accept photorealistic peeled/sliced human skin, translucent/glass-sleeved body parts, exposed wet subcutaneous vessels, or needle/pin piercings on photorealistic hands or bodies—for human surface phenomena, open on clean intact live-action exterior shots (e.g., an intact sunlit hand wrapping a neat fabric bandage beside paper) and cut cleanly to non-fleshy microscopic/cellular optics or non-photorealistic flat/watercolor illustration. When explaining non-graphic internal organ mechanics, track soft-tissue compliance via Flow `Frames` or `Extend` rather than swapping to unnamed industrial hardware (metal flanges, rollers, pistons, cutting blades). Inspect the `4–8 s` second half of every generated clip on contact sheets and normal-speed playback specifically for late morphs, detached geometry, disappearing tracer flows, or melted textures.
4. **Clean physical vocabulary, default `edge-tts` (`zh-CN-YunxiNeural`, `+4%`) continuous narration, and `Audio:` control.** Live verification confirms that Google Flow has **no dedicated TTS generator** (`/scene/` and `/edit/` have no voiceover upload lane, and `/create-tool` `Voice over` is a live microphone recorder), and `Veo 3.1 - Fast` rejects **offscreen Mandarin narration prompts** at `35%–57%` with `Audio generation failed` even when zero taboo words appear, while pure physical foley prompts succeed cleanly. Therefore:
   - Generate shared Google Flow video shots with clean physical descriptions (`"matte dark-brown two-centimeter plant-fiber blocks"` in a positive educational museum model style) and literal physical `Audio:` foley/ambience clauses (no Mandarin speech inside the Veo prompt).
   - Synthesize **Chinese (`zh`) narration as one continuous whole-episode pass using the series default `edge-tts` (`zh-CN-YunxiNeural`, `rate="+4%"`)** via `scripts/synthesize_edge_tts.py` from the `3–5` cohesive conversational chapters (never per-shot one-liners!), apply whole-track linear gain (`prepare_voice_master.py`), and composite/mux (`ffmpeg`) the continuous voiceover master onto the `1080p Upscaled` (`24/1 fps`) Google Flow video timeline with ducked Flow foley and neural-aligned `.zh.srt` captions. Synthesize paired English (`en`) narration continuously via `edge-tts` (`en-US-AndrewMultilingualNeural`, `rate="+4%"`) over the identical `1080p` visual edit (or Google AI Studio Gemini TTS / uniform native Flow `Veo 3.1` English voiceover when explicitly requested).
5. **Single-clip `1080p Upscaled` staging vs. `>> Extend` (`Omni 1.2 Flash` `+4 s`) and multi-clip `Scenes` native `720p` export.** Unextended single clips downloaded via `/edit/<clip_id> -> Download media` MUST be exported at `1080p Upscaled` (`1920×1080` / `1080×1920`, `0` credits) and verified with `ffprobe`. Note two verified platform limits: (a) clicking `+ -> >> Extend` inside `/edit/<clip_id>` switches automatically to **`Omni 1.2 Flash`** at fixed **`+4 s` (`12` credits)** and disables `1080p Upscaled` on the composite (`Download media` offers only `270p Animated GIF` and `720p Original size`, `1280×720`); and (b) multi-clip timelines assembled inside `/scene/<scene_id>` (`+ Add clip` -> `Download scene`, `10` credits) also stitch in Google's cloud at native **`1280×720` (`720×1280` vertical) `24/1 fps` CFR** without an upscale submenu—even when constituent clips were upscaled to `1080p` (use tail-frame `Frames` conditioning when `8 s` `1080p`-upscalable Veo 3.1 shots are required). Such 720p exports are internal proxies only and cannot satisfy the mandatory formal 1080p floor, even with `design.flow_scene_export="native_720p_scene"`. Use an available verified 1080p export within the commissioned tool scope or report the blocker; never silently lower the target or upscale locally to claim restored detail.

## Build a cloud-generated narration master for each language

Adapt the approved Chinese narration script into natural spoken English while preserving exact causal sequence, quantities, units, conditions, uncertainty bounds and conclusion scope under [claim-meaning preservation](science-and-rights.md#preserve-claim-meaning-through-production-handoffs) and [spoken narration craft](voice-reference.md#edit-narration-and-dialogue-for-the-ear). Keep both editions locked to the shared shot table under [narration-driven pacing](realistic-direction.md#let-narration-and-the-shots-job-set-its-length): organize visuals into coherent **spatial/lighting acts** (`wildlife act -> continuous 3D anatomical cutaway act -> outdoor closing act`, never ping-ponging daylight and dark studio on isolated single shots), and bridge adjacent shots smoothly with natural clause flow instead of freezing after every short sentence.

- **Continuous whole-episode `edge-tts` (`zh-CN-YunxiNeural`, `+4%`) narration + Flow visual compositing.** Generate **Chinese (`zh`) narration continuously as one whole-script audio master with Microsoft Edge cloud neural TTS (`edge-tts`, `zh-CN-YunxiNeural`, `rate="+4%"`)** via `scripts/synthesize_edge_tts.py` (and paired English `en` narration continuously via `edge-tts` `en-US-AndrewMultilingualNeural` `+4%`, or Google AI Studio Gemini TTS / native Flow `Veo 3.1` speech when explicitly selected), apply whole-track linear loudness mastering (`prepare_voice_master.py`), and composite (`ffmpeg`) the continuous voiceover track onto the `1080p Upscaled` (`1920×1080`, `24/1 fps` CFR) Google Flow visual sequence with ducked Flow foley and synchronized subtitles. Never route `google_flow` episodes to local `Qwen3-TTS` or OS TTS, and never slice continuous narration into per-shot pieces with artificial `1.5–2.2 s` silence gaps.
- **Anti-AI-tone script drafting and dual `(spoken_text, caption_text)` cues.** Write the narration script as `3–5` cohesive conversational paragraphs rather than `10+` standalone couplets separated by `\n\n`. Strip prompt-header colons (`“第一步靠…：”`, `“先打破误区：”`), symmetrical `[7–9 chars]，[7–9 chars]。` slogan templates, coined shorthand (`“硬带压平”`), and semicolon caveats tacked onto unrelated shots. Maintain dynamic **clause-level single-line subtitles** (`WrapStyle=2` ZH, `WrapStyle=0` EN) aligned to natural spoken phrases instead of stagnant full-shot 2-line captions, with zero SSML/markup leakage.
- **Unchopped continuous synthesis and natural J/L-cut pacing.** Generate each language edition continuously in one whole-script pass at the series default `rate="+4%"` (`|rate| <= 6%`, never `-14%` drawl). Do NOT slice continuous narration at every shot boundary to splice in repeated `1.5–2.2 s` artificial noise pauses: keep natural spoken cadence and reserve `>= 0.8 s` wordless observation holds for `2–4` major structural reveals or act closures (`>= 15%` of shots). Snap visual cut points across the `1080p` Google Flow clips to natural breath valleys with subtle `0.12–0.30 s` J/L-cut overlaps and `0.20–0.30 s` cross-act dissolves so sentences carry smoothly across cuts, keeping narration priority (`-16 LUFS` / `-1.5 dBTP` overall mix balance).
- **Audio stems and music rights.** Keep the continuous `edge-tts` narration master, Flow physical foley/ambience stems (`150–250 ms` crossfades across cuts so room tone never drops to digital zero), and optional [Google Flow Music](https://support.google.com/flow/answer/17084348?hl=en) (within verified plan rights) on distinct tracks during final `24/1 fps` `1080p` muxing so ambience ducks cleanly under speech without masking physical contact transients. [Flow Music account requirements](https://support.google.com/flow/answer/17083868?hl=en), [Google AI Pro music benefits and usage rights](https://support.google.com/googleone/answer/14534406?hl=en).
- **Canonical audio bindings.** Record `narration.voice_type="synthetic"`, `narration.execution={"status": "confirmed", "mode": "service", "location": "https://speech.platform.bing.com/consumer/speech/synthesize/readaloud/edge/v1", "confirmation_reference": ...}`, `provider="Microsoft Edge"`, `backend="edge-tts"`, `model_id="edge-tts"`, and `voice={"speaker": "zh-CN-YunxiNeural", "language": "Chinese", "rate": "+4%"}` (or the paired English `en-*Neural` speaker) in `narration.generation_record`, plus `postprocess_record` (`prepare_voice_master.py` / `ffmpeg` linear whole-track gain), and hash-verified `cloud_evidence` + input/output receipts. Never record `local_project`, `Qwen`, `synthesize_voice.py`, or `os_tts` on `google_flow`.

## Edit, mix, caption, export and review in Flow

- **Same-act chaining and coherent chapter progression in `Scenes`.** Chain consecutive shots within each spatial chapter inside Google Flow's desktop `Scenes` (`>= 1440×900` viewport) using `>> Extend`, saved tail-frame `Frames`, and `+ Add clip` (`4–7` chained clips per chapter) so geometry, camera, light, and narrator identity remain coherent across cuts rather than stitching isolated standalone clips or ping-ponging exterior and `not_observable` studio shots. Note that `/scene/<scene_id>` currently provides a single sequential clip timeline (`+ Add clip` / `>> Extend`) with **no** separate voiceover/music track lanes and **no** built-in crossfade/dissolve controls; build smooth continuity through `Extend` / `Frames` visual-and-audio chaining and natural cross-shot sentence flow.
- **Tool boundaries and honest blocker reporting.** Verify optional `/tools` (`CaptionCast`, `Mondo Sónico`, `Stringout Creator`) only when needed; they may encounter OAuth blocks, and `/create-tool` `Voice over` records a microphone rather than synthesizing speech. The [default Edge cloud narration and scoped whole-track mastering/compositing workflow](#build-a-cloud-generated-narration-master-for-each-language) is not a gap workaround. Do not use `design.flow_postproduction_gaps`, local TTS, substitute imagery or foley, unapproved providers, or FFmpeg to fabricate missing outputs or bypass a required Flow operation. If a required operation in the commissioned route is blocked, stop the affected work and report verified evidence rather than silently changing the route. [Flow Tools and credit rules](https://support.google.com/flow/answer/17104535?hl=en), [Google's CaptionCast and Mondo Sónico showcase](https://blog.google/innovation-and-ai/models-and-research/google-labs/six-new-tools-built-by-creatives/).
- **Edition-specific caption geometry.** Maintain synchronized external `.zh.srt` (`WrapStyle=2`, `>= 20 pt` legible CJK sizing) and `.en.srt` (`WrapStyle=0`, smart even line-breaking without orphaned single words) aligned to each edition's checked `caption_text` and actual clip timings. Inspect densest subtitle blocks, units and negations against spoken audio on real frames in both editions.
- **Covers across languages.** Generate clean text-free base artwork (`3:4` and `4:3`) and design [independent Chinese and English typographic covers](visual-system.md#design-the-two-cover-ratios-independently). Never publish a Chinese-texted cover unchanged onto an English edition.
- **Export resolution and stream fidelity.** Formal samples and final editions must have a short side of at least 1080 pixels and match `design.output` (default `1920x1080`, `24/1 fps` CFR). Single staged clips use `1080p Upscaled`. A 720p `Download scene` result is an internal proxy, not a deliverable; `native_720p_scene` does not waive this requirement. If no compliant export is available within the commissioned route, report the blocker rather than silently lowering the target or using forbidden local post-production. Probe actual bytes under [HD video output](quality-acceptance.md#hd-video-output).

## Audit staged clips and paired editions before delivery

Do not invent ad-hoc episode JSON schemas or ad-hoc pass scripts that omit provenance or QA structure. Bind every used cloud clip and audio stem cleanly into sibling `episode.zh.json` and `episode.en.json` records:

- Record local submission/ledger proofs in `shots[].shotbook.origin.entrypoint` and `assets[].origin.entrypoint` (classifying Flow picture assets as `ai_generated`).
- Map every shot's cloud picture asset in `shots[].asset_ids` and shared foley/ambience/music stems in `design.render_asset_ids`.
- Before delivery, run four checks across the staged clips and sibling exports:
  1. `python -X utf8 scripts/google_flow_audit.py measure <zh_export.mp4> --episode-zh <episode.zh.json> --en-video <en_export.mp4> --episode-en <episode.en.json> --report <new-flow-audit.json>` (or `--clips-only` at clip-staging time) to screen `720p` staged-clip leaks, `24->30 fps` cadence judder, clip duration overruns vs native clip length, AI-tone script markers (`clickbait_contrast_hook`, `telegraphic_short_sentences`, `slogan_closing_formula`, `semicolon_tail_stuffing`), `compressed_checklist_episode` under-length films, `world_ping_pong_cuts`, speech-rate rush, missing observation holds, and `zh`/`en` shot-order or duration divergence.
  2. `python -X utf8 scripts/opening_hook.py measure <export.mp4> --captions <captions.srt> --preview-dir <preview_dir> --report <hook-report.json>` on both editions' `0–5 s` hooks and finals.
  3. `python -X utf8 scripts/realistic_audit.py measure <export.mp4> --shots <shots.json> --delivery-fps 24 --report <realistic-audit.json>` on both `24 fps` exports.
  4. `python -X utf8 scripts/check_episode.py <episode.zh.json> --stage delivery --report <zh-delivery.json>` and `python -X utf8 scripts/check_episode.py <episode.en.json> --stage delivery --report <en-delivery.json>`.
- **Review mechanism coverage at G2 and G5.** In the existing explanation review, match the planned causal links to actual timecodes in each edition. A viewer should be able to state what causes the effect, what changes in between and how the result follows. Return skipped, visually unsupported or rushed links for added shots or observation time. Check the complete sequence at normal speed in both languages.
- **Independent bilingual G5 and SynthID provenance.** Have reviewers proficient in Chinese and English respectively watch and listen to each complete export continuously at `1.0×` speed, recording separate review identities/observations (a prompt log, file list, or `ffprobe` pass never passes G5). Preserve SynthID and provider provenance per [Flow watermarking rules](https://support.google.com/flow/answer/16353333?hl=en&co=GENIE.Platform%3DDesktop), and disclose AI-generated media accurately at authorized platform submission under [publication declaration rules](production-checkpoints.md#declare-ai-generated-content-at-publication).
