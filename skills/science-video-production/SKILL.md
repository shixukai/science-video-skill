# 科普系列视频制作

制作能让观众看清现象、理解机制的短片。以主题相关、有权的真实素材作创作锚点，在讲解合适位置展示真实对象/现象，并围绕它做标注、放大、剖面或2D机制解释；真实素材须承担解释作用，不作无关装饰。开头优先用相关真实素材，但不强制放在片头或固定秒数，首屏主题明确仍必须满足。制作任务与发布任务分别履行当前授权。

## 三个不可稀释的目标

1. **有依据的质量验收**：按 [质量验收](references/quality-acceptance.md) 对照可追溯专业参考，记录具体观察、证据与退回条件；“精美”不是可直接签收的标准，审美不伪装成自动分数
2. **系列识别**：延续已确定的字体系、配色、构图锚点、封面和声音语气；固定识别线索，不固定所有镜头和时长
3. **形式服务教学**：从真实素材中的对象与现象组织解释，原理讲解统一采用纯2D插画与动画，不用3D模型渲染或伪3D模型替代；与有权实景连贯对应，不僵化媒介比例或开场位置。示意或生成内容不能伪装成实拍证据

## 开始时

- 看本集目标、已有成片与用户最新反馈。仅缺少会改变题材、受众、事实或授权的关键内容时提问
- **受众是没有专业背景的普通大众**。选题优先自然现象与生活科学，如天气、动植物、海洋、地球、声音、光学；避免以抽象数学、统计、随机或概率教学作为系列选题，不用抽象点图代替观众可识别的现象
- 没有系列设定时，按 [视觉与声音系统](references/visual-system.md) 建立一页暂定设定；有设定则延续。用户未确认的名称、标志、色彩应标为暂定，不能声称已批准
- 分清交付范围：选题/脚本、纸上分镜、小样、成片、上传或发布。只做被要求的阶段，不把生成视频扩大为自动发布
- 检查实际可用的剪辑、转码、录音、字幕、2D或生成工具；按题材选工具。不限定 Pillow、某种生成服务或固定 30 秒。工具不足时交付已完成部分，指出缺什么，不能把粗糙占位图或机械文字轮播当作精美完成稿
- 复制 [单集简报模板](assets/brief-template.md) 和 [单集记录模板](assets/episode-template.json)。素材 `kind` 按实际形式填写，如 `graphic`、`simulation` 或 `real_capture`，不默认实拍。记录只保留推进本集所需的信息，避免为简单短片堆积流程文件
- **每条视频必须配中文语音解说**。首次先交一条音色与节奏试听，再按同系列方案制作；后续引用已交付的系列试听与反馈，不每集重新选声。纯字幕加配乐版只能标“待补录”，不能算完成
- **当前默认用 Qwen**：以 [中文自然口语技术参考](references/voice-reference.md) 为起点，在本项目独立制作试听并确认；Qwen 不可用就报告阻塞，不擅自改变已确定的声音方案或改用付费服务。后续按明确指示更新方案，不把厂商永久写死

## 画面内容边界

- **9:16 视觉满幅（全出血）**：实际场景铺到画面边缘，不预留大片独立黑/深色标题板；标题和字幕叠加，读字所需遮罩只在文字附近适度使用，不整体缩移画面。不得为填满拉伸、裁掉科学关键主体/脚点或补造影像；素材本来的暗区应与人工黑边区别。按 [满幅画面](references/visual-system.md#竖屏满幅画面) 检查实际导出首/中/尾和运动极值，尺寸或外框居中本身不算通过
- **字幕背景随文字适配**：用实际字体/字号/断行渲染后的字形外缘（含描边）加必要 padding 决定背景宽高，不用固定大横框，也不按字数粗估。换句时字幕中轴和阅读基线稳定，背景变宽/变高不拖动字层或产生跳动；分别看短/长一行、两行与换句边界的实际导出，不以缩小字号或侵入平台安全区换取小背景
- 可以放：简洁标题、与中文解说同步的字幕，以及帮助理解当前画面的必要术语、图例、单位、数字和适用条件；对应场景可保留简洁的真实性标签
- 不得常驻烧录：制作流程、版本号、测试/验收/待审状态、内部备注、模型或工具清单、流水线说明。一般来源条和制作方式声明也不要作为固定页脚反复出现
- 完整科学来源、素材权利和制作声明放配套资料或简介。许可强制的署名须保留且克制；防误解必需的“机制示意”“模拟”“AI生成”等标签及平台要求不能盲删
- 分清观众理解内容与交付记录，不把简报、台账或验收信息直接搬进视频。具体取舍见 [观众画面与交付记录](references/visual-system.md#观众画面与交付记录)

## 制作流程

### 1. 先核问题，再写承诺

确定“一句话问题”和“一句话结论”，确认观众看完能具体理解什么。开头须自然交代本期讲什么现象/问题、接下来能明白什么，再过渡到实验或机制；可以先用现象钩子再紧接主题一句，也可以主题先行，用口播与简短片内标题衔接，不能突然把观众放进实验或术语。主题只写在发布简介里不算完成；不强制冗长片头、机械“大家好今天”或固定秒数，也不制造恐惧或许诺颠覆常识。此约束用于新片和未发布片，不据此自动改动已发作品。

**片内第一屏须一眼看懂主题**：明确呈现对象/现象与一个具体问题或主题，主体视觉直接对应标题，标题在手机大小第一眼可读；不能只有美图、栏目名或抽象口号。主题口播与画面标题保持一致并自然接入解释，不要求逐字相同。封面和发布简介都不能替代这张片内开场画面；不强迫固定字体、倾斜样式或秒数，不用夸大标题，也不新增大黑标题板。该新增要求用于后续制作的新片，不因此擅改已有明确批准按现版先发或已发布的作品。

从观众见过的自然现象或日常问题出发，用生活语言讲清关键因果；精美 2D 也应有可识别的现象与对象。术语为解释服务，首次需要时先说清含义，不用专业词堆砌展示知识。简单必要的数字、单位和直观比较可以用，但不要把本集做成公式推导、统计图识读或数学课。

选题与脚本阶段先做普通读者复述检查：不补背景资料，能否用自己的话说出本集在解释什么，以及它为什么发生？记下预期复述与卡住的术语/因果步骤，先改稿或换更合适的选题，再进入制作。编辑自审须如实标明，不能写成用户或真实观众已经看懂。

按 [生产检查点](references/production-checkpoints.md) 落实：一个日常核心问题，先认识必要对象/状态，再让每个机制镜头呈现“之前状态 → 改变因素 → 结果”。标签贴近对象，同一对象跨镜头身份连续；不要用转场或装饰动画替代因果。

按 [事实与素材](references/science-and-rights.md) 建立简短的“主张 → 原始/权威依据”记录。重要数字保留单位、条件、时间；假说、模拟、相关性不能说成已证实的因果。引人注意的标题也要通过这一检查。

### 2. 选择教学形式与合法素材

- 每个关键镜头先说明“让观众看见什么”，找到主题相关的合法真实素材锚点，再选择标注、放大、剖面、2D或实景延续来解释；不随意插入图库画面，不把重复旧素材包装成新作品。所需真实素材缺少授权或不适合时如实记缺项并报告，不能用AI伪真实替代
- 选择实拍时可使用有权自摄或可核验的原始机构素材；制作2D解释时核对插画、字体、图形与纹理等权利。素材网页、下载按钮、署名、搜索引擎许可标签均不等于已获使用权
- 未获权利的候选可保留链接，不下载、不进入成片。换合法素材或拍摄；可先制作有依据的2D解释，但不能把它当缺失真实素材已取得，必要时缩小范围并报告阻塞
- 实拍不能随便代表另一地点、年份、物种、实验条件或事件。素材记录应含具体来源、作者、权利依据、用途及必要署名
- 纯2D插画与动画是当前原理讲解形式，真实素材负责对应现象与观察依据。对需要防误解的相关画面清晰标“机制示意”“模拟画面”或“AI生成画面”；比例不真实时注明。写实外观不等于真实拍摄，生成内容不能作为科学证据

### 3. 组织节奏与系列表达

围绕“看见现象 → 提出问题 → 拆开机制 → 回到真实现象”组织本集，按信息量调整长度。每镜有作用，给关键证据足够停留时间；不强制秒数或镜头数量。

按 [视觉与声音系统](references/visual-system.md) 和 [质量验收](references/quality-acceptance.md) 处理选定媒介。先对照专业参考做少量整体/细节/机制关键帧，再实际渲染约10–20秒或内容所需的代表短样，含相应解说与字幕；具体差距修复并复核后才做整片/整批。静态封面、技术名称或堆叠几何体不能代替这些证据。按真实配音留理解停顿，不固定整片或镜头时长，不加速Qwen硬塞；保留机制，减少无关动效、音乐与重复正文。

**语音、主画面和图内文字须逐段呼应**：每个解释语义段先确定口播所指的对象、要展示的动作/状态变化、就近的短标签或因果关键词，再按真实语音时码安排出现与强调。讲部位时能在图中找到它，讲变化时看到变化，讲原因时展示相应过程；底部字幕同步不能替代这些要求。不要用静止无关主图配长旁白，也不把整段口播重复塞进图里。执行 [逐段声画对应检查](references/production-checkpoints.md#逐段声画与图内文字对应)。

完成中文解说后再逐句对齐字幕与镜头节奏；配乐为人声让位。核对术语、数字、单位和多音字发音，避免赶读和不自然停顿。合成声音须在制作声明中如实说明，不克隆真人，不擅自付费购买配音服务；工具不足就明确待补录，不用静音或配乐占位冒充解说。

自然度以听感验收：像认真向朋友解释，避免朗诵腔、逐字停顿和机械等速；按连贯语义生成，长稿必要时按段落拆分并核对衔接与音色一致。不要用加速、混响或配乐掩盖生硬。已认可的短样只证明该短样符合要求，不能替代每条长稿及完整视频的实际试听。

调用外部配音服务前核对本次要发的文本、目的地、目的和已有授权。默认选择 Qwen 不等于获得无限外传许可；换目的地、发送视频或参考声音不能沿用仅文字的授权。配额或服务失败不绕过限制、不自动付费，先报告阻塞并按原授权范围处理。

### 4. 导出后必须重新看实际成片

事实、理解、美术/声音、技术、平台分别记录检查对象、方法和实际结果，不能由一个 `pass` 推断全部合格。执行 [生产检查点](references/production-checkpoints.md) 的失败处理；没有真实观众试看，写“编辑自审；理解效果待验证”，模型扮新手不能冒充实测，点击/完播也不是理解证据。

- **技术检查**：分辨率/比例/时长正确、音视频流存在、全片可解码，首尾无坏帧、黑场或错段
- **实际帧检查**：逐镜看导出帧，并覆盖片头、切换、字幕最密帧、动效轨迹极值、片尾。看实际像素，不只看坐标或脚本
- **形体与视觉检查**：按专业参考并排核2D造型/比例/关键结构、线条与色彩层次、场景功能、排版构图、运动连续性及科学边界；保留实际全景、关键细节放大和连续片段。图层穿插错误、非预期或无依据的漂浮、接缝、闪烁、无依据占位形体、关键遮挡/裁切等缺陷须退回，不以“精美”或任意分数自动通过
- **下方解说字幕**：实际位于画面下方可读区域，不能居中占住主体却称底部字幕；检查最长两行与换句边界，和图内标签、真实平台UI分别核对。不用统一Y坐标或画布百分比代替实测，也不缩小字号来勉强塞入
- **画面文字检查**：逐镜读实际导出的全部文字，含标题、字幕、角标、页脚、图例和转场，确认没有内部制作/验收信息；必要真实性标签与强制署名仍在。OCR 可辅助，不能替代逐镜检查
- **主体居中与分层布局**：以实际导出画布尺寸确认几何中心，不能沿用子画布中心；主体默认视觉居中，同时看完整轮廓、光学重心与四周留白，不能仅看代码坐标。主体与字幕/平台 UI 安全区分别布局，禁止为躲字幕或界面而统一缩小、左移或上移整个画面造成偏位和大块空白。非居中须有明确叙事理由；首/中/末及运动极值实际帧、连续小样通过后才批量应用。用户质疑偏位时，撤销对应版本的视觉通过并复核
- **手机与平台预览**：在已授权的实际目标账号，用最终标题、完整简介/tag、已加载的实际平台 UI 检查首/中/末和动态字幕，核对用户名、互动栏、文案的遮挡；视频或文案变更后重查。裸播放器、静态安全区坐标或代理缩图不能代替，浏览器手机样式预览不称实机；缺权限/条件写明待平台检查或未做实机检查，不宣称已适配
- **科学与声音检查**：逐段并实际试听完整导出，确认中文解说自然、与稿件一致，术语/数字/单位发音正确、停顿连贯、音色一致；字幕同步，口播/字幕/封面事实一致；实拍与示意标签完整，配乐不遮人声，无突刺/削波/突断。异常时长、疑似重复/漏词/跑词先拦截核查，不直接装片或猜根因。短样获认可不能替代该项；无法实际试听就记“未验”，不能宣称完整交付
- **大众理解检查**：回到没有专业背景的观众，复核能否复述现象与核心原因；只有真实反馈才能写成用户已理解。用户明确表示看不懂时，当前内容验收失败，应改稿或换题，不以技术检查、ASR 对齐或画面精美为由继续判合格。已发布作品的修改/删除须另有对应明确授权，本 Skill 更新不产生该权限

全片解码成功只说明文件能播放，不等于视觉通过。脚本、助手自填的勾选项或少数漂亮截图也不能替代实际观看。修改任一媒体后，相关验收和文件校验值需重做。

用户整体否定一批作品时，冻结该批当前交付/发布状态，重新检查共同根因及全部质量维度；不能仅修被点名处就恢复整批通过。保留认可且仍匹配的音轨，避免无谓重生成；完整实听与真实新观众理解分别验，未做标未验，模型评审不能冒充真人测试。已发作品不据此自动修改。

### 5. 交付完整单集包

成片交付应包含：

- 带中文语音解说及同步字幕的视频文件（适合本集和当前目标端，竖屏通常从 9:16 开始）
- 标题，最多 30 字；简介与 tag 合计最多 1000 字。工具按 Unicode 码点保守初查，最终看平台实际计数
- 两张分别排版的封面：3:4、4:3；重新安排主体和标题，不能机械裁切或拉伸
- 简短来源/权利记录，以及制作声明：哪些真实拍摄、哪些机构素材、哪些模拟/AI、哪些重要处理；可放说明文件/简介，必要真实性标签仍要放在相关镜头中
- 当前版本的实际验收记录及未完成项。未经实测不写“全部通过”

不 @ 好友，不塞无关热点/无关 tag，不使用强营销或夸张恐吓话术。不要为满足标签数量凑词。

用本目录的 `scripts/check_episode.py` 检查本地包：

    python scripts/check_episode.py path/to/episode.json --stage plan
    python scripts/check_episode.py path/to/episode.json --stage delivery

路径相对 JSON 文件所在目录。`plan` 仅验证计划结构，明确列出待取得的素材；`delivery` 检查实际文件、长度、来源关系、权利记录、中文解说记录、尺寸、全片解码及验收校验值。`narration` 记录语言、制作状态、声音类型、解说素材 ID、合成声明和首次系列试听引用；未做的状态保留 `pending`。需要 Python 3.11+ 与本地 ffprobe/ffmpeg，脚本不会联网、下载或发布。它不能独立判断科学真伪、合法性、好看与否或手机体验；存在音轨不能证明有中文解说，`qa.narration` 必须来自实际试听及字幕同步检查。其 `review_scope` 只有在实际试听当前完整导出后才可填 `final_export`；短样填 `short_sample`，未试听填 `pending`，两者都不能通过完整交付检查。

`plan` 用于已有科学依据的制作计划。只有早期想法且来源未核实，可以留草稿，但不要补假 URL/核验日期来通过检查。平台检查按 [生产检查点](references/production-checkpoints.md) 记录到 `qa.mobile_preview`；`review_scope=target_platform`，`surface` 区分实机与桌面平台预览，绑定实际账号、标题/简介/tag的校验值。自填字段不能创造验收事实。

`qa.comprehension` 区分 `editor_reviewed` 与有实际反馈引用的 `audience_checked`；尚未审查用 `pending`，已知理解失败用 `fail`。编辑自审不能宣称观众已懂，后两者不能通过完整交付检查。用户指出具体缺陷时，相关旧视觉/内容通过改为待复核或失败，不能由技术通过覆盖。

只有实际审完当前导出后，才把对应 `qa` 项改为 `pass` 并写具体检查记录；将这三份媒体文件的 SHA-256 填入 `qa.reviewed_sha256`。可用系统的 `sha256sum` 等本地工具计算。算出校验值不代表已经审片，脚本不能代签；自填的 QA 字段、文件解码或自动指标也不能证明内容好懂、画面精美或平台无遮挡。

## 上传与发布边界

交付成片不代表可直接发账号。上传、定时或发布前，确认已有具体授权覆盖账号、这一版内容与动作；没有就询问。发布时核对当前平台规格、简介计数和预览，不把本项目的默认值写成平台永久规则。

上传完成不等于发布成功。仅在实际看到发布成功状态、可核验作品链接/ID或平台回执后报告“已发布”；审核中、草稿、定时、失败分别如实说明，不重复盲发。不因失败转为公开其他位置、付费买素材或更换账号。
