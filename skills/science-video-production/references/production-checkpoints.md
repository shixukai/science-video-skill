# 从研究到可执行的制作检查点

写实主画面及任何非写实替代先执行 [写实制作契约](realistic-production.md)；旧2D默认不能覆盖当前视觉目标。连续短样须实看实听并独审后才能作为扩片依据，技术测试不替代验收。
用于写脚本、做代表性小样和验收本集。以下是结合研究与本项目经验的实施建议，不是整套经实验验证的配方；不保证播放、完播或涨粉。按本集实际画面、声音、内部审查及可选真实反馈调整，不能只勾选表格。

## 1. 先确定观众要看懂的一件事

制作前先按 [成人选题筛选](topic-contract.md#成人受众的选题筛选) 完成现有brief中的选题卡，淘汰只验证常识、复述定义、改标题或被现成资产牵着走的题目；先审是否值得讲，再推进下列G1解释设计。

在 brief 写三句：观众见过什么、哪里值得问、看完能解释或判断什么。优先寻找日常直觉与真实观察之间值得解释的差异，或一个能用画面追查的问题；具体好奇缺口的科学、题意与开场边界按 [主题契约](topic-contract.md#开场与观众范围) 执行，不为制造意外改写事实。观看收益须落到本题的任务，例如能凭什么观察区分两种现象、解释一个常见误判或判断条件改变后的结果；“了解更多”“看到最后有惊喜”不能代替。围绕原题必答范围组织，结尾用日常话把观察、已建立关系与答案接回开头，不因修复局部而新增支题。先让观众认出整体问题和可观察现象，建立一句准确的整体关系，再进入必要机制细节；总答不能代替后续关系与证据，细节也不能挤走整体答案。

G1 的“选题六项”统一指六组内容：①主问题及必要从属问题、主从关系和必要性（没有从属问题写明，不设固定数量）；②目标观众及可合理假定的知识起点；③一句话答案及看完能说明或判断什么；④画面必须呈现的关系或必要变化；⑤本期必答范围及范围外内容；⑥可能误解与禁画。分别落实到主题锚点、brief、必要前提和解释分镜，不另建重复表。三句摘要用于开场组织，不能替代六组信息；无特殊误解或范围外内容时说明依据，不为填项虚构问题。

写完整纸稿时，每个新增概念都要回答：它帮助解决原题哪一步？理解它先要知道什么，前面何处已建立？画面能指向哪个实际对象、关系或变化？没用途的删，前提未建立的先补，必要术语用日常话并就近对应；不强塞名词表或让观众先学会复杂图例/视角规则才知道在解释什么。别把更长、更短、更多术语/标签当成更易懂的证据。

开场主题、第一屏与口播安排按 [主题契约](topic-contract.md#开场与观众范围) 执行；此处把“哪里值得问”对应到真实观察、解释路径和具体观看收益，检查它如何自然建立后续解释所需的前提，不能突然把观众放进实验或术语。无需先铺一段百科背景才交代值得看的问题，也不强制每期同一问答句式。

产物：原题的简短答案、必要前提及各概念的用途/前置关系。按首次观看者能够获得的信息作编辑复述检查，不用创作者知道但片中没交代的知识补空；用自己的日常话回答原问题，并指出首次不能接上的一步。若只能复述操作路径、术语或标签，却说不清回答原问题所需的关系、条件或证据，先删减支线或补前提，再改稿/分镜，不进入整片制作。编辑或模型演练须如实标明，不称为真实普通观众测试。

## 2. 把解释关系变成可见表达

先识别需要建立的关系，再选择表达。因果用前态、改变因素、必要过程与结果；空间用参照、方向、视点及约束；结构与功能用部件、连接及作用；比较用同条件案例与关键差异；数量用量、单位、关系和成立条件；概率用可能结果、分布与不确定性；证据用观察、推断及其限度；传播用载体、路径、传递和局部响应与整体传播的差别。只填写本题实际需要的类型，不为非因果问题虚构触发和变化。按理解依赖顺序揭示，预告、回顾与正在发生的机制须可区分；开场简短总答不代替后续解释。沿已有解释分镜写清各段怎样兑现开场承诺：给观察证据、补必要前提、排除一种合理解释、建立关系或验证一个预测，按本题选择。段落若只重复提问、预告惊喜或增加无关信息，先删改；已能说明的答案及时说明，后续好奇由尚待解释的关系和证据承接，不故意藏住关键条件或把同一答案拖到片尾。

每次切镜或镜内解释模型切换，成对设计前镜终态与后镜初态：前面已建立什么结论，后面怎样沿用它推进回答，哪些对象与空间锚点保持，哪些视角、尺度或状态需要改变。后镜据此承接制作，不能各自完成后只补一句转场原因。有意换对象/地点时先建立新关系，不能让观众误认同一连续过程。放大先定位整体中的目标再进入局部，返回时能认回原位置；转视角、剖面或尺度变化交代前后对应。可用构图、匹配动作、连续镜头、简短解说或必要标注完成，不强制新增上屏字或固定转场特效，叠化本身不是桥接。

单变量演示保持其它相关对象、位置和条件不变；存在本题必须解释且有科学依据的中间过程时，先展示它再引出结果，不为顺序要求捏造阶段、可见偏差或时延。不能同时重排整个场景，让观众猜哪一项导致变化。动画需有可读的起点、过程和终点，跟随真实口播的语义推进；说到变化时变化开始，解释过程时看见过程，结果出现后留观察时间。允许有目的的预备与停顿，不按机械毫秒阈值验收。换状态或移动后检查旧层退场，避免旧对象残留成第二个主体或鬼影，除非明确用于比较。标签贴近对象，必要的放大、变速、模拟按实际情况标示。

产物：可逐行对照的解释分镜，记录在 topic_alignment.coverage[].explanation_steps；causal_steps 仅兼容已有因果计划。共同字段 id、relation_type、prerequisites、key_relation、derivation、boundary、referent_mappings、handoff、shot_ids、requires_dynamic、key_difficulty；静态表达另记 still_reason。key_relation 说明对象怎样关联，derivation 说明该关系怎样支持本段结论，boundary 写明条件、示意或推断限度，referent_mappings 将图形/标签/视点对应到真实对象与意义。一个必要范围可以组合多类关系，但所有 required_scope 的承诺都须有完整解释路径；不能仅检主链而漏掉从属承诺。已有 coverage.explanation_type 及其旧类型字段按兼容映射读取，不要求同时填写两套类型记录。缺必要前提、推理跳步、对象突然变义、参照断裂或实际画面未呈现所述关系，均先修分镜。

每个解释步骤的 `prerequisites` 逐项记录 `knowledge`（本步沿用的具体知识/结论）及 `source`：`audience_prior` 表示已列入 `brief.audience_start.assumed_knowledge` 的合理受众前提；`step` 同时填写来源 `step_id`。来源步骤必须已在片中建立所需关系，不能用后文知识或开场先给的一句话总答补当前缺口。来源步骤的最后一镜不得晚于本步第一镜；共用同镜时按 coverage 及 steps 记录顺序表示先后，并与实际呈现顺序一致。旧 `explanation_steps` / `causal_steps` 的字符串前提须在重新验 G1 前迁移，不能自动假定为受众已知。检查器只核引用和记录顺序，关系是否实际建立仍由纸稿及有声草排审查判断。

### 每个关键难点的表达方案

在 topic_alignment.expression_cards 为关键难点填写 difficulty、prerequisites、visual_action、inferable_outcome、misconception、boundary，以及 step_ids 与 uncertain。visual_action 必须具体说清固定什么、改变什么、展示顺序、比较哪两个状态、放大哪个局部或持续保留哪条联系；“做直观动画”“突出重点”不足以执行。卡片及解释配方的 prerequisites 仍是规划所需信息的文字清单，来源绑定记录在对应解释步骤；必要前提可合理来自受众起点，仍须写明。没有特殊误解或简化时写出依据。

拿不准的关键难点（uncertain=true）先比较至少两个低成本表达方案，variants 记录具体动作、low_cost=true 和 explanation_effect；selection 指定采用方案、理由及比较项 missing_prerequisites、reasoning_gaps、relation_visibility、ambiguity。只对不确定的关键难点做对照，不给每个镜头强制两版，也不把两种配色当两种解释方法。G1检查目标与推理，G2检查方案和有声草排是否实际建立了这些关系。

| relation_type | 需要记录的关系字段 |
| --- | --- |
| causal | before、change、after，必要中间过程写入分镜 |
| spatial | objects_positions、constraints、reference_frame、spatial_relation，涉及视点时交代观察者 |
| structure_function | components、organization、structure、function、mechanism_link |
| comparison | compared_cases、controlled_conditions、difference、inference |
| quantitative | quantities、relationship、conditions、common_scale、denominator、sample_scope、uncertainty |
| probability | outcomes、distribution、interpretation、uncertainty、common_scale、denominator、sample_scope |
| evidence | evidence_basis、inference、limitations、alternative_explanations、inference_rule |
| propagation | carrier、path、transfer，区分局部响应与传播范围 |

可从 [解释配方](../assets/explanation-recipes.json) 选骨架并按本题改写；配方不提供本题科学依据，也不代替实际美术资产和动态审查。

### 逐段声画与图内文字对应

对每个完整解释语义段写一行对应关系：实际口播句 → 被讲述的画面对象 → 对象动作或状态变化 → 必要时的就近图内短标签/关键词（无需添加时注明画面如何讲清） → 真实音轨时点与最终导出证据。按语义段而非每个字强制动画；字幕、图内解释与主题标题各有职责。

- 说部件或对象时，让观众在主画面定位它；必要时高亮或移动视线引导，标签贴近所指对象
- 说变化或因果时展示必要过程；说比较、空间、结构、数量或证据时，呈现对应的条件、参照和联系。实际口播与画面事件一致，不能提前显示下一阶段结果
- 必要图内文字简短解释正在看的动作、关系、条件或数值，术语与口播一致；先做文字删除测试，不为每段配字。主图必须承载对应解释，不能只有底部逐字字幕在更新，也不应复制整段旁白造成重复阅读
- 同一对象跨镜保持身份与含义；局部放大、剖面、视角或类比切换先交代关系。类比不能代替真实机制，也不能把类比结论直接当完整解释
- 开场必须有明确的片内主题陈述，说明本期要解释的现象/问题；现象钩子、疑问或画面标题本身不能自动算作已经明确交代。允许自然措辞，不强制固定问候、句式或秒数

解释相对位置、朝向或观察关系时，先建立可识别的参照对象及方向对应；涉及观察关系时，还须建立相关观察者或视点，使观众知道“相对谁、从哪里看、朝向哪里”。已建立且当前仍可追踪的画外参照、第一人称视角或抽象模型可沿用，不强求所有对象每帧同屏，不为无关关系强加观察者。用点、轴、线或局部框替代实体，先展示其与该实体/视点的对应，换视角后仍能认回同一关系；不能让未建立映射的坐标和标签独自承担解释。说“这里、那边、这个方向”等指示语时，对应时点的所指对象或区域须清楚可辨、定位无歧义，可通过取景、对象姿态、局部强调或必要引导实现，不强制增加箭头或文字。参照缺失、指代目标弱小/多义或映射断裂，退回该镜分镜和关系布局；仅补一个对象图标、标签或更粗的线不构成修复，须重新核完整关系。

验收先静音检查主图和图内文字能否让人定位对象、变化与关系，再带声连续逐段对照口播、动作、标签及字幕的真实时点。静音检查不是要求画面独立讲完全部细节，带声检查也不能仅以转写或时间码匹配代替。记录检查版本、时间点、实际对应结果和缺项；填写映射表不创造验收事实。用户指出解释混乱或声画脱节时，当前内容验收失败：重查解释结构与分镜，不只补一句片头或修改底部字幕后沿用旧通过。

## 3. 阶段推进与代表样

先核当前任务允许的阶段。设计系统整理、私有样片、整片制作及发布是不同范围；暂停时保存现状，不由旧日程或规则更新自动恢复。完成某前置阶段后继续制作须有当前任务覆盖。

返工和任务委托须沿用原请求及用户最新明确范围，传递请求引用、最终交付范围、允许改动与保留项；不能仅凭一张截图、一个时码或方便实施，把整片修复擅缩成局部替换。内部先做代表段时保留整片尚待处理和验证的范围，不把试验边界改成最终任务上限。用户明确只改或只审局部时遵循该限制；新指示扩大范围或撤销旧限制时，同步更新委托，不能继续用过期的“其余不动”阻止必要返工。同类排查、修复范围与最终证据按 [失败后的处理](quality-acceptance.md#失败后的处理) 执行，不另建台账。

按下文 [G1–G7](#g1g7-的实际推进记录) 逐关推进，产物、前置、失败退回与回执以该表为唯一阶段定义；主题、视觉、声音及逐镜方法分别引用对应正文。

局部修复优先沿用仍匹配的已认可音轨与素材，不为迁移索引重新生成。无法渲染或实际看听时，标具体缺项并继续可独立做的纸稿/设计；明示待审交付不等完整放行。每阶段记录实际版本、当前结果、下一步和未验项，不以成本、素材数或工期代替品质。

## 4. 按真实解说安排理解节奏

先保全必要机制，删掉支线与重复，按解释路径写成连续完整讲解稿，再按理解任务划分语义段、安排分镜，最后用实际配音确定时点。解说稿须回答观众此刻在看什么、为何发生和为何转到下一步；尽早给出能推进问题的第一块有效信息，随后让新观察或关系产生继续看的理由，不能把各镜独立写成短文后拼接。连读时只用此前已建立的信息推进。改镜头顺序或结论时，先修完整稿及受影响的承接段，再重新拆镜。先补缺失前提、指代或推理桥，再决定是否需改配音，不能只换音色、加字幕或加连接词掩盖逻辑断裂。难点后给观察、对比和消化的停留；判断停顿、重复和支线是否有理解用途，不能把快速切镜当吸引力，也不能为固定总时长删关键解释步骤或加速 Qwen 硬塞。

难点出现时降低无关粒子、背景运动、切镜和抢耳音乐。保留必要的中文可访问性字幕，不把“减少冗余”误用为删字幕；同时避免又叠一段重复正文。精美与清楚要同时达到，少元素并不自动等于高质量。

优化持续观看时，按 [持续观看设计细则](viewer-retention-design.md) 将上述逐段兑现与节奏方法落实为下一观察任务、关键发现的声画编排、存疑段删改对照及结尾回看。沿用本页解释分镜、动作卡和阶段记录；方法服务于已有标准，不新增固定秒数、问题数量或完播保证。


### 开工锁定与真实渲染入口

每次实际制作先锁定正在使用的Skill版本与全部文件哈希；每个待制镜头先写清讲什么、主体、主体怎样动、注意对象与观众应发现什么。缺设计不能开工，已知失败不能扩整片；修复后重新实际审查再继续。已有认可真实成片时先对照该片做同风格有声动态样稿，不能擅换造型语言，也不能以静态参数、代码检查或补填记录代替实际执行与审美。

沿用 `shotbook.claim_support/subject/action/attention_target/viewer_takeaway`，不新增平行分镜表；每次制作或恢复前用 `render_gate.py lock` 新建只写一次的锁文件，把其相对路径和SHA-256填入 `execution.skill_lock`。锁内记录实际安装版本、全部Skill文件哈希及整体摘要；“最新版”、仓库提交名或安装记录不能替代实际字节。升级后须明确迁移/复查受影响内容再建新锁，不能伪称旧版本工作使用了新规则。

在 `design.approved_film_reference` 绑定项目真实认可的成片、原认可来源/证据与适用画风，按实际观察范围留证；认可媒体和用户审片记录只放私有单集。首个待审样稿可依据有限的真实静帧观察做外观候选：沿用 `viewing`，明确 `method=frame_samples`、`scope=approved_film_visual_reference`、`purpose=appearance_only`，绑定完整原片哈希/时长及 `frames` 中每帧的源哈希、真实时点、图片路径/哈希、实际打开和观察内容。此时 `watched=true` 仅表示已看列明静帧，须诚实填 `heard=false`、`playback_speed=null`、`ranges=[]`；不声称连续观看、动作或听感通过。已有真实连续视听记录可直接复用；无需每次制作前重审旧基准全片。有限基准观察只帮助制作待审候选，G3/full仍须新样稿真实连续视听和同风格对照，最终整片审查不变。不是让每集重新询问已有风格批准。未取得该真实基准时可继续查找、设计和准备，不能用通用风格图冒充成片对照；仅内部线框实验须明确其范围，不交作符合画风的样稿。

将当前工程实际渲染适配器以 `execution.entrypoint={file,sha256}` 固定。适配器接受 `--episode`、`--phase sample|full`、有序 `--shot-ids` 与 `--output`，按这些输入调用原渲染器，禁止忽略范围、另读未绑定的旧方案或扩大输出。用 `render_gate.py run` 包住真实调用，不把检查命令写在日志里却另行直调。适配器只能由该入口启动；外层脚本须在非零结果时立即退出，禁止检查命令后用独立shell行继续调用Node/Python渲染器。入口在启动前将实际设计、Skill、代码和输入摘要写入新回执；阻塞时不会运行适配器；运行完成只记 `rendered_unreviewed`，不修改任何QA通过状态。工程适配器的实际范围执行须用该工程集成测试核对；通用脚本不能约束任意外部程序的行为，也不授予渲染之外的权限。

- `sample`：核选中镜头设计、版本锁和实际认可成片，不依赖尚未产生的G3或最终整片证据。保留已知失败，允许在当前授权内修复并产生新的有声动态候选，不能无限停在静态文件或补签历史。成功后把真实回执绑定 `execution.sample_receipt`，实际看听该样稿，并在既有 `qa.visual_frames.animation.style_comparison` 记录基准/样稿哈希和同风格对照结论。
- `full`：必须指定整期全部镜头，先重核已完成的G3、当前样稿真实调用/产物及同风格对照；未关闭美术、声音、技术或反馈失败阻断扩制。首个样稿不会因此被要求提前通过G3。修改样稿设计、基准、适配器或Skill后旧回执失效，先重新制作并审样稿；通过后才能扩片。
- 完整候选完成后将回执绑定 `execution.full_receipt`。G5–G7自动核最终导出绑定与真实调用先后，复用既有完整连续观看和双环境听验记录，审看/审听者须与制作人不同；技术、视觉、听感分别判定。没有实际看完/听完就保留未验，字段齐全或测试通过不代表美学、科学或听感通过。

每轮记录阻塞原因与下一项可执行修复，修复后重跑同一适用阶段，不能删失败记录、换范围名或拿局部用户认可给整片放行。用户明确要求查看失败候选时只交该版本、该范围并如实注明失败/未验；这种交付授权不把任何技术/审美结果改成通过，也不授予发布。既有 `qa.release` 继续单独负责实际发布授权。

## 5. 质量判定的唯一入口

执行 [质量验收](quality-acceptance.md) 的分项检查、未验门槛与反馈闭环；视觉几何/字幕制作方法见 [视觉系统](visual-system.md)，配音方法见 [声音参考](voice-reference.md)。本页只决定推进顺序，不另维护同一份QA清单。明示的用户整片理解失败必须退回，不用技术通过抵消。

## 6. 从导出到实际平台完成检查

只有已获所需上传/预览授权时才进入平台。使用实际目标账号，填入最终标题、完整简介与 tag，等平台 UI、文案和预览真正加载；保留用户名、互动栏、文案等实际覆盖区域，查看首/中/末、最密字幕、转场及运动极值。文案长度可能改变遮挡，不能只用短标题预览代替最终文案。

记录预览来源：实际手机/平台发布页预览/本地播放器，以及导出版本、最终文案和关键时间点截图。浏览器中的手机样式预览不能称为实机；被截图裁去画幅边界时不能反推完整 9:16 坐标。没有实机条件就写未做实机检查。

发现关键字幕、单位、标签或主体被挡住时，做最小布局调整，重新导出并在同一最终文案/界面下复查，不能沿用旧通过记录。改视频、标题、简介、账号或相关展示方式后重查。没有平台访问或授权时可交待平台检查版，不能宣称已完成平台适配，更不能自行发布。

在 `qa.mobile_preview` 记实际 `platform`、`account`、`review_scope=target_platform`，`surface` 用 `actual_device` 或 `desktop_platform_preview`，`note` 记录看到的结果与截图/时间点；裸播放器或代理缩图不能填成它们。实际复核后再填 `reviewed_metadata_sha256`，由本地 `check_episode.py` 的 `platform_metadata_sha256(data, preview)` 对标题、简介、tag、平台、账号与预览来源计算，缺失时检查器会显示当前值。计算/复制哈希不代表验收；它只帮助发现后续文案或目的地变更使旧记录失效。

## 交付包与发布回执

按 [系列配置](../config/series-profile.json) 提供带中文解说/同步字幕的成片、标题/简介/tag、分别排版的3:4和4:3封面、来源/权利与制作声明、当前验收记录/未完成项。文案长度默认由配置和本地检查器保守核验，最终看实际平台计数；不@好友，不凑无关热点/tag，不用夸张恐吓或强营销。平台规则可能变化，使用时核实际要求。

上传、定时、公开发布前，核已有具体授权覆盖账号、内容版本和动作；已有批准不反复问，范围/风险变化另按当前权限处理。交付或采用本Skill不等于发布授权。仅实际发布成功状态、作品ID/链接或平台回执才能记已发布；审核中、草稿、定时、失败和结果未知分别记录。未知先查重/回读，不能盲目重发；失败不自动改账号、付费或公开到其他位置。已发或被取消/禁止内容不因规则更新重新投放。平台实测缺条件时可交待平台检查版，不宣称已适配。

## 研究依据与适用边界

- [National Academies，2017，Summary](https://www.nationalacademies.org/read/23674/chapter/2)：委员会框架强调目标、受众和情境；不是“单条一问”或日常题必胜的实验。本节主从问题组织方式是实施取舍
- [Mayer 等，2002，预训练实验摘要](https://pubmed.ncbi.nlm.nih.gov/12240927/)：学生观看制动器/气泵动画，先认识部件状态有助迁移测试；不是中文自然短视频平台试验
- [Mayer 与 Moreno，2003，证据总结，第46–48页](https://carpentries.github.io/instructor-training/files/papers/mayer-reduce-cognitive-load-2003.pdf)：支持减少无关加工、提示与标签邻近、声画对应。它不是单一新实验，不能直接推导删字幕或固定切镜时长
- [Mayer 与 Chandler，2001，分段实验](https://tecfa.unige.ch/tecfa/teaching/methodo/Mayer_Chandler01.pdf)：研究学习者可控节奏的闪电动画与迁移表现；不是固定视频暂停长度的直接证明，分段与交互/学习时间须区分
- [《The Green Planet》制作人访谈，2022](https://www.thenakedscientists.com/articles/interviews/green-planet-filming-secrets)：研究故事与开发拍摄技术并行，技术用于显露过程；属第一手制作案例，不能证明某种媒介必然更易懂
- [KQED Cracking the Code 项目总结，2022](https://www.kqed.org/about/16895/cracking-the-code-millennial-science-media-habits-and-engagement)：结合调查、实验与实践，提示区分受众、平台和指标；点击/意向/投入不等于理解，也不能直接外推抖音涨粉
- [TikTok In-Feed Ads，Safe Zone](https://ads.tiktok.com/resources/help/article/tiktok-auction-in-feed-ads?lang=en)：截至2026-10-06所读版本说明安全区受画幅、简介长度和附加形式影响，预览与实际设备可能不同。这是 TikTok 广告文档，不是抖音自然投稿硬标准；本项目仍以实际抖音界面验证，不固定通用像素线

## G1–G7 的实际推进记录

完整标准按硬门槛H与内部可校准起点D执行，数值唯一来源为 [制作策略](../config/production-policy.json)。D不是可静默省略的要求：按起点实施，改变时记录样片、理由和校准证据；H未知或失败不能用分数抵扣。设计素材是参考，不能按候选文件自带状态认定生产批准；系列具体风格/字幕/已认可声音以现行配置优先。

在同一 `episode.json` 的 `brief.roles` 指定制片/主编、科学编辑、编导、美术动画、声音字幕、审片、发布负责人。一人可兼岗，工时合并；作者自查和独立审片使用不同任务上下文，模型数量不是真人数量。制片对最终版本负责，不能把技术诊断或普通修复转嫁用户。仅在真正缺少风格选择、重大题材决策或当前规则要求的批准时请求决定，既有授权不重复索取。

| --- | --- | --- | --- |
| G1 | 选题六项、事实卡、全部必答范围的解释结构、必要前提、难点定位、禁画清单及科学/逻辑内审 | 正式脚本/分镜 | 缩题/研究 |
| G2 | 经核脚本、难点表达方案内审、真实工作音轨、整期声画表及完整有声草排；正常速完整看听并逐个审查相邻镜承接 | 成品美术/动作验证 | 脚本/镜头顺序 |
| G3 | 整景/中景/机制三尺度美术图与最终造型、真实音轨、正式字幕的连续代表动态 | 仅已验范围的同体系扩制 | 美术/动作 |

| G5 | 当前完整版本的科学、解释与表达独立内审、L3精美程度、声音、字幕、技术及观看舒适审查 | 提请或使用已获具体版本批准 | 对应工序 |
| G6 | 锁定发布包、实际平台预览、权利/标识及覆盖该包的授权 | 指定平台提交 | 发布包/适配 |
| G7 | 实际作品ID/链接、发布时间、平台状态与内容匹配读回 | 计入唯一实际发布/复盘 | 未知先查重，失败修复 |

`qa.gates.G1` 至 `G7` 仅引用现有QA记录，不另造平行审批。状态为 `not_reviewed`、`needs_changes`、`passed`；取消为 `cancelled`。每个通过含实际审查者、时间、范围、证据文件及哈希、所引用QA与对应上下文摘要。没过的前置不能从后关倒填通过。G2允许低精细度，关键状态/整期范围不能缺；`plan` 检查通过允许范围明确的草排待审交付，不代表G2通过。先探索风格可并行，G2/G3未过不批量精制作。G3返工可以保留整片失败状态，不能拿局部通过清掉它。

G1 可用 [相对阶段计划](shotbook.md#无音轨的-g1-纸面计划) 记录先后语义阶段与观察任务，不为尚未合成的音轨编造秒数或观看证据。实际调用千问前按 [声音参考](voice-reference.md) 检查当前及前文上下文指定的工程/服务位置；已有明确指定直接使用，未指定才询问，整理规范和纸面计划不触发位置询问。进入G2前取得真实工作音轨并转为实际时点，再实际看听完整草排。

G2 在连续播放中逐个核相邻镜接缝：前镜实际建立了什么，后镜实际沿用了什么，画面怎样让人认出同一对象/参照或知道已换对象。只用截至该处已呈现的信息判断，首次接不上的位置、所见所闻及修复结果记入现有 `qa.shotbook` 证据；修复后连同前后段重看，不能用单镜分别通过代替。此检查不要求画面脱离解说独立解释全部细节。

G2的低精细度指尚未精修，不授权更换已批准的造型语言。内部技术草排可用明确占位形体；已有批准画风时，交用户审看的工作稿须按 [已批准设计的实际落地](visual-system.md#已批准设计的实际落地) 使用基本符合该方向的实际可见资产。偏离批准造型的工程占位形体只能作为内部技术证据，不能借“G2允许粗艺术”、技术通过或标注“未验”冒充符合画风的美术结果；用户明确要求查看技术线框/占位稿时，可按该范围交付。此边界不要求G2提前完成G3的全部动作精修；技术帧、内部G2稿、风格审看稿和整片分别说明实际范围。

常规系列可复用已验证风格；新对象/机制仍验代表动作。新风格用同一科学事实、配音与解释结构比较两套方案，防止同时换题/音色无法判断；长度随完整变化需要，不凑固定秒数。样段明确适用范围与例外，再扩制。

将封面完成度迁入影片时，G3代表段按 [完整场景方法](visual-system.md#从封面完成度到可控动态场景) 覆盖整体定位、关键关系与结果回接，不用孤立的精绘组件支持整片扩制。

具体获准的历史2D范围的外观方向由 [已确认视觉锚点](visual-system.md#已确认画风的视觉锚点) 固定，正式风格候选按 [实际资产方法](visual-system.md#从视觉锚点到实际资产) 先完成静态推敲及制作端美术回查，再交对应范围审看；不因处于G1/G2或标未批准而把工程占位当风格提案。此要求针对候选所承担的静态外观，不前置G5整片或连续声画验收。等待声音等独立缺项时，可继续这部分美术工作；进入有声草排和后关仍须满足其实际条件。

美术方法在既有阶段内推进：G2用 [色彩与构图缩略带](visual-system.md#整片色彩与构图缩略带) 检查整期选择和关系；G3按 [实际风险选样及同镜校准](visual-system.md#代表样与-l2l3-校准) 验证精修后的主体、构图和连续动作；G5检查完整最终编码的L3完成度与细节保留；G6在已获授权的实际目标平台预览中复核可观察的细节及遮挡。发布后转码成品尚未取得时另记待验，不要求先发布才能完成G6预览。前期缩略带可为粗稿，不能把G3的精修要求提前变成G2门槛。证据、失败与未验沿用 [美术方法的阶段证据](quality-acceptance.md#美术方法的阶段证据)，不增加关卡或重复风格批准。

## 产能、成本与复盘

R为熟悉机制常规片，N为新对象/机制，B为新风格/标杆，质量硬门槛相同。日更与研发分队列；实际唯一发布、追加任务、取消项与样段分别记账。缺合格库存如实报目标差额，不自行降频、不拿失败上传/重复片抵数。当前任务的每日目标属于项目配置，不证明产能。

当前系列按 [项目配置](../config/series-profile.json) 分别执行每日 **10条完整制作**（`operations.daily_completed_unique_target`）与每日 **10条实际有效唯一新发布**（`operations.daily_actual_unique_target`），两项分别报实际数、目标和差额，不互相抵扣。日期按配置时区：完整制作计当天首次完成且G5实际通过的不同完整单集；发布计当天首次有效发布且G7读回核实的不同作品。沿用项目台账的 `production_ledger` 与 `publication_ledger` 分别记账；未知实际数和差额用null，不写成已达标。保留作品ID、媒体版本/哈希、新作品范围依据、完成时间、当前G5质量证据及G7首次发布回执，G4待审候选不能计完成，不能只按文件数、尝试次数或计划数量计数。

样片、草稿、渲染中、旧片或失败版本均不得抵扣，重复版本/重复上传也不得抵数。旧片如另有发布批准，可如实记平台活动，但不能自动计入每日10条新作品达标；合格未发布库存是否属于本次新作品范围，须由来源、版本及实际记录确定，不默认全部计入，也不因此停止当前制作或反复询问。昨天已完成的成果不能重复记今天制作，已经发布的旧片重传必须排除；既有未完成视频继续制作，只有实际完整完成、当前G5通过且符合新作品范围证据，才计入当日制作。目标不降低反馈、美术、声音、科学、权利或发布门槛；缺口如实保留。这次配置纠正只更新目标与计数口径，不新建或改变日程，也不据此推断过去实际按何数量停止。


每片记录各岗位有效工时、机器占用、排队、返工次数/来源与工时、付费素材/声音/计算成本及币种，订阅分摊写方法。按策略中最初10片实测、20片按R/N/B观察中位数及保守分位数，少样本同时保留逐条数据。同一人多岗位合并负荷，审片与发布也是瓶颈，机器并行不等于审片无限。单位合格片成本=观察周期内全部制作成本（含失败片、研发与返工成本）÷最终通过质量门槛的不同作品数，分母0记不适用；不能只计成功片的成本。

采用策略中的在制实验上限、常规成批起点与缓冲库存目标；库存是已批准未发的不同作品，不是假设已有。连续两批瓶颈过载，依次收窄问题、删无必要新场景、复用已验证资产、修返工点；补外包能力须另有预算/交易批准，交付含源文件、关键态、权利范围，不自动购买。不得降低验收标准。

复盘分三组：生产健康（首次整片通过率、P0/P1、返工/排队、合格库存、实际发布与差额）、解释质量（内部发现的缺失前提、推理跳步、关系不可见、承诺未兑现及修复结果；有授权取得的观众反馈可附加）、平台表现（平台原名字段、定义、分母、窗口、采集时间及媒体版本）。缺数据用null，不推算成事实；播放、关注、订单、收入分开，未知收入不是0。24/72小时与7天为快照起点，不自动新建监控。真实留存数据在已有台账保存原始回执或导出，私有账号、作品及反馈不进入公共Skill；无曲线仍可完成内部审查，不要求观众实时反馈。

有留存曲线时，把下降、趋平段或重看峰值的实际位置对回已发布版本的声画任务，分别检查开头是否迟迟没有明确问题/有效信息、正文是否缺前提/重复/转镜失联/答案不兑现，以及片长是否包含可删支线或确有必要的解释。峰值可能来自兴趣，也可能来自看不懂后的重看，不自动称为高光。只有总体完播率时，不能定位流失段或认定开头是唯一根因；同时看平台可提供的平均观看时长、各段留存及其定义，避免把较短视频更容易看完当成解释质量更好。必要观察停留与科学步骤不能为了完播删掉。

比较先匹配平台、题材、片长、发布窗口、分母和流量来源/受众范围，再看可比作品中位数及样本量；缺口、样本小或推荐流量变化须明确，不能把外部基准直接当本片可达到的效果。沿现有台账提出带位置和证据的下一轮假设，一轮改变一个主要创作变量，保留前后条件与结果；非受控比较只支持相关与待验证假设，单条高播放、总体完播变化或跨平台上传不证明开场、画风或时长的因果效果，不保证改动后的留存提升。

### 平台选题与数据复核

平台研究须保留可核来源、采集时间、数据更新状态、统计窗口、作品年龄、样本与分母；缺失、未更新和真实零值分别记录。口径未对齐的数据不能拼成统计结论，平台建议与观察相关不构成已证实因果或执行授权。

选题时优先读取当前有权访问的创作者中心：科普领域话题/作品信号、自己往期作品的真实数据和平台AI建议，回填现有选题卡与私有项目台账。保留入口、作品/页面身份、领域、排序与时间筛选、来源证据及采集时间；无访问权限、页面空榜或尚未更新就准确记缺口，继续可做的事实研究和编辑判断，不冒称完成调研或虚构实时反馈。平台数据补充成人选题判断，不替代事实主源、解释回报或已有质量门槛。

- 先核页面原始统计起止、更新时间与更新节奏、作品发布时间及发布后年龄、时长、样本范围和指标定义/分母。页面时区未标明时保留原样并记未知，不擅换时区或计算精确作品年龄；累计播放与固定窗口数据不能混排。分母或样本未显示就记未知与限制，不用当前播放量乘百分比反推准确人数。
- 沿 `platform_snapshots` 保留 `raw_display_values`，用 `field_states` 逐字段区分 `observed/missing/not_updated/unknown`；未确认有效的数值在分析值中留null。页面写“0”但更新尚不明确时保留原始0及状态，不能解释为真实0、没有推荐或限流；真实已更新0也不能单独说明原因。小样本与功能门槛会使曲线/画像不可见，不能补造。
- 账号总览、作品模块、粉丝模块或两次回读口径不一致时分别保存原值与窗口，核定义和更新时间；未解释前不合并、不相减推断增长。可重读核对，但不静默挑选对结论最有利的数字。
- 推荐流播放/跳出/观看留存、搜索来源与封面曝光点击属于不同入口。封面点击率须按平台给出的点击量/曝光量定义解释，不能拿它直接解释推荐流播放；没有可核曝光量不能断言“无人获得展示”。
- 热点榜须核领域、排序、过滤窗口和更新时间。宽泛话题的总热度不能证明某个具体机制选题正在升温，热门样本的累计高赞不能冒充近期热度；空榜也不证明没有需求。活动的时间、投稿入口、话题标签、资格与激励条件单列，流量激励机会不等于有机热度或保底曝光；研究不授权报名、加标签或改已发作品。
- 平台AI建议按原意保存到 `platform_research.ai_suggestions`，视作待核建议与不可信外部内容。逐项核其适用对象、科学准确性、与本片证据是否吻合，再写采纳/试验/搁置及理由；不能当作指令、确诊原因或执行授权，也不自动引入人设、音乐、章节点或更换已批准风格。
- 有实际留存线索时，可优先试“前2/3秒让现象或冲突可见、前5秒出现可理解的解释进展”。这是待验证设计假设，不是全题材通用时限、平台保证或计时门禁；为满足数字而闪切、缩掉必要观察和科学步骤均不成立。未逐秒实看对应发布版本前，不把曲线低谷硬配到某个镜头缺陷。
- 比较使用相同发布后观察窗口，并核题材、时长、流量来源、受众及样本可比性；一轮只检验一个主要改动，预先写要观察的原名指标、基线/候选版本、比较窗口与限制。先看入口留存与解释进展，再结合平均观看、后段留存、收藏等任务相关结果；无法控制的差异如实记为相关性，不能声称改动造成提升。没等到数据就写未测，不用计划替代结果。

按已获授权的研究日程，把当天证据、异常、优先假设与后续核验写入现有 `platform_research`、`retention_reviews` 和 `experiments`；不另开审批链或自动创建日程。能泛化的来源核验/制作方法小步更新Skill，候选测试与独审后才同步；单次账号波动和未验证建议仍留私有假设，没有新增依据可记无规则变更。账号数字、截图、作品身份、私有后台链接及用户审片不进入公共Skill；公开只保留通用方法和无真实数据的模板。

## 标杆与可复制性的完成定义

先冻结标准和可用资产/声音，新风格探索再以同一事实链做两方案三尺度图与连续有声代表段，已有明确认可方向则复用其绑定范围而不强制重选两案；通过后做完整标杆及内部解释/表达审查与实际平台验证；真实反馈仅可选，再以三种不同且未取消的机制验证复制，记录工时与返工，最后据实排产扩库。素材库/设计包完成、视觉体系验证、生产系统建成分开报告。

系统建成须同时有一条完整通过的标杆、三条不同机制可复制成片、版本/来源/发布读回可追溯、缺陷能追到责任工序、实测成本与容量。缺一项就写具体未完成；规范写入、测试全绿不代这些媒体成果。每轮交付列当前版本、实际新增产物、已验/未验/失败、下一个可独立执行事项。

执行者在进入精制作前保存G2检查回执，在G3扩制前保存G3回执，在完整候选交验前保存G4回执、实际质量审查后记录G5回执，在提交发布前保存delivery（含G6）回执，发布后再核G7。检查失败或缺回执必须停在相应关；不能绕过检查器直接调用渲染/发布后补通过。脚本本身不劫持外部渲染器或平台，执行责任人和独立审查要核真实调用/回执与产物版本。

导出默认格式/码率等D用制作策略并记实际偏差和依据；ffprobe记录实际帧率/恒定性、色彩信息、流和时长，解码检查损坏；源色彩标签不足以证明转换正确。所有版本由同一主工程导出，不下载已发片反复压制。可保留高质量无平台下载水印母版，不能移除必要AI/作者/许可标识。跨平台版独立核排版、字幕、标题、许可和预览；同步设置按项目既有指示核实，不擅改、不将未核同步说成功。

### 实施参考的用途

以下只支持相应方法，项目自定分数/产能不由外部来源背书，使用时核当前文档：
- [Ordinary Folk流程](https://www.ordinaryfolk.co/process)：脚本、设计、动画和声音工序
- [Motion Canvas事件](https://motion-canvas.io/docs/time-events/)：可维护的声画时码；经局部验证后可选，不是品质证明
- [Remotion Skills](https://www.remotion.dev/docs/ai/skills)与[许可说明](https://www.remotion.dev/docs/license/faq)：实现参考与按主体核许可，不自动安装或认定商业资格
- [FFmpeg loudnorm](https://ffmpeg.org/ffmpeg-filters.html#loudnorm)与[ffprobe](https://www.ffmpeg.org/ffprobe.html)：测量/媒体信息能力，不为内部响度起点背书
- W3C [文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[闪烁](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html)、[预录字幕](https://www.w3.org/WAI/WCAG22/Understanding/captions-prerecorded.html)：内部检查参考，不等全片认证或所有人的安全保证

已有可用渲染器先保持，不同时迁移主渲染器、声音模型与美术体系。每轮规则迭代分别记录文档、技术、连续代表段、完整成片四层回归；静态/动态/失败/声音/字幕/全片标杆参考集由项目私有证据维护，有固定版本、范围和实际批准才使用。

当前系列同步例外在series-profile.operations.platform_sync配置：按既有安排保留观察到的同步设置，不独立核附属平台结果，未核不算成功且不作为主平台阻塞。该项目例外不自动推广到其他项目，也不授权改变同步或新增发布。

每个统计周期在项目台账asset_reuse中关联asset_id@version、实际复用单集、成功/失败适用性、返工原因/工时变化和证据。没有数据保持未测，不把文件复用次数当有效复用或自动宣称节省工时；不因此新增监控。

单期不再用一个笼统status覆盖混合阶段：当前阶段由工作记录说明，各关状态以qa.gates为准。source_ids是sources[].id中被实际主张引用的ID集合，不是完整source对象数组。授权核查状态 `qa.release.authorization_status` 与包就绪status分开；其他质量/平台项失败不抹掉已有效授权，也不重复问同一批准。

制片/主编负责收窄选题、分配工作、控制版本、维护事实来源与发布队列，并交选题卡、排产和变更记录；只报进度不能代品质通过。审查者先看指定成片，再看作者解释，首次卡点不得被事后讲解覆盖。发布失败在qa.publication.note分别写执行拒绝、权限缺失、用户取消或网络/技术失败及实际证据，不笼统写系统卡住，不绕过新的明确拒绝。

规则回归的version_change分别记录拟变更的from_version与to_version，可在proposed阶段填写；actual_commit仅在真实提交成功后记录，二者不得互相代填。

## 全片覆盖与扩制边界

G2的整片镜头表须从0覆盖到实际整期音轨结束，各段连续且有明确镜头身份；局部样段表不能冒充全片。既有检查按实际时码与音轨时长核缺口，纸面相对时间方案仍留在plan，不据此扩制。

G3允许保留整片失败状态继续局部修复；准备扩制时，在 `qa.visual_frames.animation.next_action` 写 `expand`，核既有失败记录。`whole_episode`、`series_style` 或 `segment` 的未关闭美术失败阻断扩制，不以技术通过、换名字或局部通过清除。局部修复用 `repair_sample`；G4完整候选同样不得携带这些未关闭问题。真实修复与复查按原失败证据规则关闭，不自动写通过。

## 从参考学习到实际改进

用户给出优秀作品、要求持续提升，或当前成片暴露具体差距时，在已有制作记录内做一轮有产物的学习；选择与当前难点相关、可实际观看的代表作品，不以收集数量或播放量证明价值。学习方法不等于获得素材许可，也不授权重做已发布/取消内容或新增发布。

1. **先看，再定位差距**：核参考身份、版本/链接、时长及实际观看范围；评价整片编排须覆盖开场、主要解释段、应用/收束及接缝。对关键动作看连续段，记录时点、屏幕上实际发生什么、对象怎样接续、条件/过程/结果如何可见。单帧不能证明动作，未实听就不评价配音或声音节奏；无法访问/覆盖就明确未验，不凭缩略图、作者说明或他人概括补成实看。参考的科学陈述另核原源，不能直接继承医学数值、奖项或效果。
2. **提炼可试的改动**：将参考中观察到的方法对应到当前影片的具体失败点，写出改哪个镜头/关系、预期改善什么、保持什么不变，以及不适用之处。区分“参考中看见”“迁移推断”“本片已验证”；学习对象可追踪、变量与结果联动、景别和段落组织等方法，不照搬他人的媒体、配音、文案或独特镜头资产。参考的3D、暗色、粒子、景深或镜长不自动变成系列规则，仍遵守本期写实目标及具体获准的模态、已确认画风、角色、科学与权利边界。
3. **在授权制作中落地**：若当前请求涵盖实际应用，先选尚未完成影片里覆盖该难点的连续代表段，沿用有效音轨、事实与工程，只改变本轮要检验的关键表达；按现有G2/G3推进并实际导出。不能交完分析报告或改完Skill就称应用完成。当前仅有研究/Skill权限时，只交候选方法与待应用范围，不擅自修改媒体；缺原素材或制作能力时记录具体阻塞，继续可独立的准备。
4. **实看对照后取舍**：保留修改前后版本、相同解释任务和可比观看条件，实际对照关键帧、手机显示尺寸及正常速连续声画；看关系是否更清楚、主体/场景是否更成熟、有没有新科学或可读性损失。有效才把本片证据支持的适用范围沉淀为可复用做法；无效就修正或弃用，未验保持待验证。Skill可先写入证据边界与候选实施步骤，但不能把尚未应用的方法写成已证实的品质提升。更新既有责任正文或删改无效规则，不因每看一部作品堆一套门槛；样段通过仍不代整片。

沿用 [美术与画质记录](../assets/art-direction-template.md) 和实际阶段QA保存“反馈/差距→参考时点→拟改动→代表段版本→实看对照→保留/修正/弃用/待验”，不另建审批或自动定时任务。按用户本次范围完成应用、验证及Skill保存；尚缺实际媒体证据时明确这一未闭环项，后续仅在仍有效的授权范围继续。通用方法与事实/媒体权利各自核实，参考链接和私有审看记录不自动进入公共Skill。

## E02–E07：精制作前的解释设计

事实核查后、有声草排前，在现有简报和范围记录中完成一页解释设计，不再建立平行审批。先解决怎样解释，再写完整正式口播；不能把未解决的理解断点交给美术精修或后期补救。

- E02 观众起点：分别列可合理假设的知识、本片必须先交代的对象/概念/参照及范围外内容。复杂关系前先能辨认对象；不无限追溯常识，但缺失就无法理解下一步的前提必须先交代
- E03 结构：标注因果过程、空间约束、结构功能、传播、数量、概率或证据推断，可按实际解释分支组合。写清前提、关键关系、结论和边界，不把所有题材套为触发—变化—结果，不用知识名词清单代替推导
- E04 推理：逐个核因为、所以、因此、从而等连接是否有足够前提；缺变化、约束、对应或证据就补足。命名和宣布结果不算解释；已明确接受的合理前提无需无限下钻
- E05 分段：按认识对象、观察变化、建立对应、比较或得出结论的理解任务分段，不按固定秒数。控制同时新增的重要关系，不机械限制每镜只有一个物体或每句只有一个名词；说明每段如何接到下一段
- E06 整合：把原现象、已建立关系和最终答案重新对应，不仅重复结论，不在收尾引入未经解释的重要概念
- E07 选表达：由难点决定方法，不能为复用现有模型、素材或转场反过来改写解释。说明方法让哪个关键关系可观察；以下选择表是工具，不是统一模板

| 关系类型 | 可选表达 | 不可省略的观察依据 |
| --- | --- | --- |
| 因果过程 | 连续状态、局部放大、接触/作用 | 中间变化与前后联系 |
| 空间约束 | 固定参照、视角转换、条件筛选 | 不变量及满足条件的位置/方向 |
| 结构功能 | 整体定位后剖面、分层、往返 | 位置、连接与相互作用 |
| 传播 | 分离局部响应与传播范围 | 物体运动和整体传播的差别 |
| 数量 | 共同尺度、受控对照 | 改变项、不变项、数量基准与完整分母 |
| 概率 | 分布、范围、相同基准比较 | 样本范围、分母、不确定性，不以单次结果代规律 |
| 证据推断 | 分开观察与推断 | 得到什么证据、能推出什么、不能推出什么 |

每个关键难点按 [表达方案](#每个关键难点的表达方案) 在同一 topic_alignment.expression_cards 记录四项：理解难点（具体关系断在哪里）、必要信息（依赖前提）、表达动作（固定/改变/展示/比较什么）、推导结果（足以支持的结论）。表达动作按该难点需要指明先后状态、对照对象、局部放大或持续联系；“做直观动画”“配图说明”不是制作指令。简化与误导风险一并交给 [E11–E12审查](quality-acceptance.md#自主解释与表达审查)，不能因四字段重组而删掉边界。

拿不准的关键难点（uncertain=true）先低成本比较至少两种方案，按前提缺失、推理跳步、关系明确度、歧义选择；不按特效数量或专业感选择，也不要求所有镜头双版。草排低精细度仍须呈现关键关系；对应 [阶段表](#g1g7-的实际推进记录) 审查后才进入精制作，最终声画整合后再次检查解释是否成立。

解释设计记录还包括主从问题、合理观众起点、说明/判断/区分目标、完整关系路径、难点、表达与镜头映射、简化/误导、内部检查证据与修订结论。可选真实反馈单列，空缺不构成阻塞。可复用解释方法记录适用问题、对象映射、不适用范围、误导风险和曾失败/改进的依据，不能把漂亮演示强套所有题材。

主体动态的定义、长静帧上限、ROI筛查、语义段记录与G2/G3/G5失败门槛统一见 [质量责任正文](quality-acceptance.md#主体动态与长静帧)；逐镜静态方向认可不替代对应动态证据。

G1用途计划及G2/G3/G5实际文字与声音连续证据按 [可见文字责任正文](visual-system.md#可见文字用途与制作辩解) 和 [整期旁白责任正文](voice-reference.md#整期旁白连续性) 执行；缺项保持未验，不为补证据恢复已否定成片。

## 精确可控与高效迭代

本节负责逐镜可控性、试验边界与执行效率；仅规范当前已获授权阶段内的方法，不新增机器门禁，也不放宽写实、科学权利、实际版本锁、G3或独立连续实看实听。局部无声技术测试仅在该范围已有明确许可时适用，不能替代有声代表段、成片验收或发布。具体路径、模型、阈值、素材与回执留在项目工作包。

### 动作状态与可见成功条件

逐镜先写动作起态、关键转变和终态，列出主体、参照物、接触或遮挡关系、运动方向与应保持不变的身份；成功条件必须能在实际画面中辨认，不能只写“自然、真实、精美”。将“应看见什么、在哪段出现、什么现象算失败”对应到正常速度观看和必要相邻帧检查。确需受力、因果次序或量值准确的镜头，优先用可核科学观测作研究依据，生产画面选已核实授权的用户自拍或自行制作且可核参数、边界和简化的可控模拟；第三方观测影像不进入交付视觉，按 [原创视觉来源契约](science-and-rights.md#原创视觉来源契约) 区分；AI环境画面不得充当机制证据，可控模拟也不自动等于科学正确。

### 固定基线与有据假设

每轮保留可追溯基线和实际输入版本，只改变预先写明的设计变量；确需联动修改时逐项列出，不把多变量差异称为严格单变量结论。比较须用相同可见成功条件和可比展示尺度，记录输出实际差异、失败与未知，不用提示词变化推断改善。图生视频可约束主体、构图或起态，但不保证接触次序、液体运动、物理机制或更高质量；从文生切到图生同时引入初始视觉条件，不能简写成已证明的因果优化。实际条件图、节点连接与生成起态须分别核验；静图推拉不算生成连续运动。

### 静态证据条件复用与动态新鲜检查

不可变环境、工具和模型来源核验可有条件复用：原记录须可读且绑定实际文件、校验值、版本、来源和原检查范围，并有可信未变依据；换文件、配置、解释器、加载路径或核验范围失效时，重查受影响部分。仅同名、曾经成功或复制旧回执不证明当前仍相同；缺少可信完整性依据时重新核实际文件。是否允许缓存复用还取决于当前冻结入口，入口要求现场重哈希时照做，不为提速绕过它。

使用“已验证且不变的执行器＋每轮不可变参数和资产清单”，避免为每个候选重写硬编码入口。当前附带两个有限候选适配器：[49帧原始无声 I2V](../scripts/bounded_i2v/README.md) 与 [Blender 三关键帧](../scripts/bounded_blender/README.md)。两者仅覆盖各自 README 的既有能力和授权范围，不能替换 render_gate、origin_guard、G3 或科学、美术与视听验收；条件图实际来源权利仍须独审，哈希不证明原创。冻结核心由不同候选配置复用；配置绑定实际输入、设计、权限、版本及有限参数，图节点、连接、argv 与资源边界不得因配置化而扩大。源码、依赖、权限或原审查假设改变时重新审受影响部分，不用旧签名覆盖新行为。已提供合成/离线测试；目标 Windows 的解析、编译、纯测试与真实 GPU 执行分别报告，不把离线通过称为生产通过，也不自动替换历史入口。未经实际比较不宣称节省时间；动态资源仍逐次现采。

实际执行者身份由受控本地启动及锁证据绑定，不再要求云端逐轮抄写 holder 身份后等待手签；这不是取消独审或本地身份核验。已有静态独审先完成，冻结入口在本地连续执行动态采集、资源检查与受限提交，避免人为跨端往返使快照过期。

资源余量、实际服务身份、任务唯一执行者、队列与时限每次提交前重新采集和验证，不复用上一轮动态快照。静态独审与大文件校验尽量先完成，再采集动态证据并在提交前复核；不得把旧时间改为现在，也不得为适配等待时间扩大既定新鲜度窗口。唯一执行者是本任务防重复提交，不凭桌面进程存在就声称整机独占；未知重负载或证据缺失按实际资源策略停止，不擅杀其他任务。

### 一次提交与最小恢复记录

实际提交前先持久保存最小恢复记录：任务和候选身份、冻结输入/执行入口引用、一次提交占位、执行者及时间；收到结果后及时关联服务返回的任务标识和原始状态。同一候选出现超时、断连或未知结果，先只读核对该任务的队列、历史和已有输出，不盲重投、不换目录重置一次性记录。只读核对仍未知则保留未知并暂停重投；确认未执行后的恢复也必须符合现有入口及授权，不能删除证据冒充首次调用。 明确区分已证实未提交（known noPOST）与可能已提交但结果未知（unknown POST）；仅前者可依实际证据和原授权建立有记录的恢复候选，后者保留任务级一次性记录及跨引擎未知状态标记，先只读核对，不通过换目录或切换渲染器逃避未知状态。采集失败的原始样本、命令结果与失败原因先落盘再报错，不能仅保存异常摘要或事后重造现场。

### 分段计时与受控服务复用

正式推理仅用实际推理阶段可核的开始与结束记录计时；只有服务任务级起止时标为服务任务耗时，纯推理耗时保持未知，不把含加载、编码的任务耗时或客户端等待冒充纯推理。端到端另分静态核验、排队、模型加载、推理、编码、输出核验、实际审看反馈及归档；阶段可能重叠，记录口径与重叠，不能简单相加或把模型缓存后的快轮次当作全流程普遍提速。

已获授权的受控批次可复用仍合规、身份和配置未变的现有服务及已加载模型，逐次动态检查和一次提交约束仍成立。服务复用不授予启动、安装、更改安全设置或扩大持久运行权限；不擅停无权管理的服务、不清别人的队列。退出、观察预算和清理按既有权限与实际任务归属执行；观察超时不等于GPU已停止，无法安全只处理本任务时先报告而不是全局中断。

### 输出审看反馈优先与归档

输出产生后优先核真实文件、尺寸、帧数、时长、音轨及输入/任务绑定，再实际连续审看并反馈已观察结果；关键接触相邻帧可补充，但缩略图和静帧不替代正常速度播放，技术通过不等于科学、美术或听感通过。适用的有声阶段仍须实听和独审；局部技术候选明确非最终样片、AI非实拍，未看的部分保持未验。

最小恢复记录和当前媒体身份必须先落盘；之后有权限的冗长归档、复制与汇总可异步，不阻塞已有实际结果的审看和及时反馈。异步归档须保留目标、当前状态和失败续接点，未完成不宣称已备份；不能借异步省略来源、入口、一次提交或媒体绑定，也不能因此绕过上传权限与阶段交付门禁。

### 硬失败止损与优化声明

开轮前写清硬失败条件和本轮停止边界；达到边界即停止该方向，不以无依据的提示词重写或seed扫描拖延。仅在权限仍覆盖且有新证据支持可检验的新假设时，才提出下一项有界候选；新假设必须说明失败原因、改变项和预期可见差别，不能把未知当继续试验的依据。用户要求最后一次或停止时严格终止该范围。

未经实际对照测量的缓存、批次、条件输入和流程优化都只是候选方案，不宣称提质、提速或科学正确。报告分别列已实施、已测结果、适用条件与仍未知；某次候选通过、某轮更快或单项目经验不自动成为跨模型、跨题材结论。
