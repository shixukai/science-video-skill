# Video subagents

For complex production or repairs with independent work or required independent review, actually invoke the applicable specialized roles; naming roles in a plan or installing their files is not delegation. The parent remains the director and integrator: it owns the user's scope, scientific explanation, shot order, current approvals, shared episode/shot records, final decisions and delivery. Small edits can stay with the parent. Six role definitions do not mean six agents must run on every task. Before user-facing animation review, the parent/editor applies [moving animatics and user review](quality-acceptance.md#moving-animatics-and-user-review) to actual timeline/source coverage. An inherited brief, accepted model or internal storyboard does not approve prolonged still-board substitution; return known missing action to the motion/edit owner without another user repair test. Preserve intentional observation/comparison holds and scientific invariants.

## Roles and ownership

| Role | Delegate when needed | Owned output |
| --- | --- | --- |
| [`video_researcher`](../agents/video_researcher.toml) | Scientific mechanism, engineering sequence, analogy, viral angle/package, hook-lab candidates or platform-data research needs evidence | Source-backed mechanism/sequence notes, appeal-screened angle and package proposals, at least three sourced two-second hook candidates, platform metric notes and script corrections |
| [`video_visual_artist`](../agents/video_visual_artist.toml) | Assets, structural detail, the hook shot's first frame and phone-feed readability, covers, composition, material or light need work | Assigned geometry/material/light/cover modules or asset files; their interface and preview requests |
| [`video_animator`](../agents/video_animator.toml) | Frame-0 motion for the two-second hook, process interaction, shareable visual climaxes, rigging, character performance or camera choreography is substantial | Assigned motion/rig modules, shared-state/event mapping, caches and preview requests |
| [`video_audio_editor`](../agents/video_audio_editor.toml) | Front-loaded first line, hard audio/caption start, re-hook pacing, prosody/level continuity across shots, timing, subtitles, sound or editing needs dedicated work | Assigned narration/audio/edit/subtitle files, continuity diagnostics and a render/mix execution request |
| [`video_producer_windows`](../agents/video_producer_windows.toml) | Local Blender/MoneyPrinterTurbo/vork/model/FFmpeg execution or authorized multi-platform publication needs a known owner | Actual job submission (hook sample first), monitoring/recovery, new media, `opening_hook.py` reports and technical/publication receipts |
| [`video_reviewer`](../agents/video_reviewer.toml) | An independent explanation, audiovisual expression or scroll-viewer appeal review is required | A new scoped review report tied to actual files, times/frames (including the cold two-second test at frame 0/1 s/2 s muted and with sound, swipe-risk points and promise fulfillment) and perception capabilities |

The parent owns the complete narrative: overall context, this episode's question and payoff, each case's role, section progression and the ending. Apply [whole-film direction](viewer-retention-design.md#direct-the-whole-film-before-polishing-its-parts) within the existing [explanation design](production-checkpoints.md), not only to the opening. An agent may draft a complete script, but the parent integrates and reads it before full synthesis or batch refinement. Local technical completion cannot settle story meaning, and giving the audio editor the whole track does not transfer the director's responsibility. It does not outsource the whole film to unrelated per-shot agents. Roles reuse the [one global Skill](global-skill-installation.md), not their own copies of production standards.

## Shared assignment contract

When a commissioned platform review supplies a next-production brief, the parent integrates its specific change, responsible role, affected continuous segment and testable metric into the existing assignment. The researcher owns cohort/intent and evidence limits, authors own the actual script/picture/edit change, and the reviewer verifies media implementation after the cold-view pass. No role may convert an unmeasured platform hypothesis into an audience-performance pass or resume old published works from maintenance alone.

The narrative-context instructions below apply to authors, not the initial cold-view packet for an independent reviewer. Use the two-phase review packet below for that role.

For narrative-bearing work, include the overall context, current episode question/payoff, selected package promise (title, cover concept and the selected two-second hook with its first frame, first line and payload clause), the assigned section's contribution and re-hook, its incoming/outgoing connection, and a reference to the current complete script/outline. Reuse the existing assignment message and brief; do not require another schema. A local defect report or shot description alone is insufficient context. The child reads that context before authoring, flags a missing connection or promise/evidence mismatch, and proposes a bounded correction for the parent to integrate. It must not invent the film's purpose, broaden the episode or silently turn its local case into the main topic. Pure asset/execution tasks need only the context that changes their assigned decisions.

Give each agent the current user request and corrections, task/shot IDs, stage and route, global Skill path, relevant existing inputs with versions, exact file/directory ownership, expected output and dependencies. State whether the commission is instruction/tool/role maintenance or actual media production/repair, and preserve it through follow-ups; a referenced failure does not itself authorize project takeover. For an appearance deliverable, assign the actual shader/light source and `purpose=appearance` execution path, not only adjectives or a motion-preview template. Maintenance tests use isolated fixtures and do not resume the cited project. State whether execution is authorized now or only a plan/module is requested. For G6/G7 publication assignments, include production-checkpoints.md's standing preferences for all available platform associations, eligible monetization, download controls and [required AI declarations](production-checkpoints.md#declare-ai-generated-content-at-publication), including AI narration. Include the actual account/work scope and any current override; return each destination's actual settings and outcome in the existing consolidated release record. Apply [proportionate acceptance](quality-acceptance.md#risk-based-rechecks-and-evidence-reuse) to the assignment: identify the actual scientific/visible risk and reuse existing checks. Neither parent nor child may turn implementation tolerances, exact part counts or an engineering topic into an unrequested simulation/certification commission. No extra checklist or approval is required. Include any pause, cancellation or prohibited version. For a changed picture-text request, include the current user-message/evidence reference and the old brief/layout directions it supersedes. A keep-model/continue instruction does not revive withdrawn annotation permission. Resolve the current correction in the plan and generator before the next preview; preserve earlier instructions as history rather than leaving a known violation in an unresolved role conflict. Use the existing task message and work log; no extra episode schema or approval stage is needed. For video repairs, include the stable repair scope, observed defect/expected change, current playable version, next continuous deliverable and task-specific diagnostic allowance from references/blender-execution.md. The producer returns exhausted allowance, missed forecasts or recurring defects to the parent; the parent resolves the cause instead of relaying another isolated-frame request. Renaming jobs or opening another scope does not itself constitute progress.

All agents work in a shared workspace. They must preserve others' changes, stay within assigned ownership, and return an integration request for shared files. Give each shared `.blend`, `vork` `scene.json`/Slang module, timeline, episode record or colliding output name/namespace one writer at a time. Explicitly assigned disjoint files may be written in parallel in one directory; directory location alone is not an exclusive lock. Keep a shared render prefix, manifest or aggregate index with its designated writer. A useful split is geometry/material modules versus animation modules with agreed object names, units, axes, frame range and callable interfaces (including [supporting `vork` shots](tool-routing.md#vork-execution), which retain single-writer scene/shader ownership and never silently replace Blender or MoneyPrinterTurbo). Parallel agents must not each rebuild the same scene or synthesize a separate narrator for every shot. The audio editor owns one canonical narration timeline/master and shared processing recipe; visual-shot jobs and local visual repairs reference that continuous master without independent per-shot gain/pitch/loudnorm resets or patchwork micro-splicing. Give the producer the adopted mix-preset ID, `continuity_diagnostics` status/flags and actual source/processing records; keep narration-stem and final-mix measurement scopes separate.

All roles read the current global `SKILL.md` and only the responsibility references needed for their task. The task's current instructions and approvals control the role's scope. Role configuration grants no new production, installation, upload or publication authorization. Inherit the host's tools, model and permissions; do not invent capabilities or weaken settings. No recursive delegation unless the parent explicitly requests it.

Return a concise result: assigned scope; changed/created files and versions; actual checks with evidence paths; known defects/unreviewed ranges; dependencies and next action. Keep large media, frame sequences, models and logs local. Bandwidth conservation is mandatory for every role. Before any media submission, apply the [hard pre-submission requirement](tool-routing.md#review-media-without-repeated-uploads); do not submit if necessity, deduplication or payload selection is unresolved. Assign one owner per review responsibility, version and range. The parent consolidates findings into one prioritized repair packet; do not commission equivalent reviews or validators from several children, or make the parent reopen every frame already inspected. Return paths, concrete defects and the next affected-scope check. Required independent explanation/expression responsibilities remain separate. Apply the [risk-based review and evidence reuse](quality-acceptance.md#risk-based-rechecks-and-evidence-reuse) contract: one actual viewing and canonical timeline may support several QA items within the same responsibility/version/context; derive required record views instead of repeating manual ledgers, and use targeted diagnosis for concrete risks rather than per-frame or per-visual-cut quotas. The separate G5 explanation and expression reviewers still inspect their actual assigned media in their own context. Local execution and human/model perception are separate capabilities; agent identity alone does not establish either.

## Scheduling and handoff

1. The parent settles the overall context, episode question/payoff, [appeal-screened package](viral-appeal-and-packaging.md#design-the-package-before-the-script) (title candidates, cover concept, two-second hook from the [hook lab](viral-appeal-and-packaging.md#run-the-hook-lab-at-g1)), whole-script progression and route. Research, angle/package comparison and asset feasibility can run independently; integrate their findings before locking the affected script/shot design.
2. Once the affected narrative and interfaces are stable, visual, motion and audio/edit work can proceed on separate files. In 3D, apply [critical-asset qualification](engineering-blender.md#qualify-critical-assets-before-whole-film-integration): the artist owns the shared asset, while interface design and cheap blocking may proceed independently. Hold detailed whole-film adapters, repeated shot-by-shot compatibility scans and dependent beauty renders until the asset is usable for that scope. Do not keep downstream agents adapting a visibly failed version. Give the difficult visible relationship one accountable author through the complete changed cycle and its joins; the parent integrates the result, rather than repeatedly relaying isolated endpoints. In realistic work, the animator owns control/motion design within the selected route, not automatic replacement by Blender-looking final imagery. Validate the actual difficult relation in a playable prototype before expanding refinement or upscale work; the existing G2/G3 still decides expansion. Audio changes return to the editor and invalidate affected timing/lip-sync alignment.
3. A designated producer owns this work package's job queue. Authors may inspect assets and run scoped lightweight code checks locally; coordinate renders, synthesis, simulations and other heavy work through that queue. One queue owner may run multiple non-conflicting jobs when measured throughput and responsiveness support it. This is not a one-process limit, a GPU-utilization cap or permission to interfere with other tasks. Delegate one coherent authorized package covering its normal build/decode/encode/validation and non-content technical recovery. Specify the target playable output and any distinct purpose for extra intermediate encodes in the existing assignment. New material/light risks use or validly reuse material-rendering.md's grouped samples before costly complete-interval rendering; zero/exhausted diagnostic allowance returns an unresolved preflight decision to the parent and never mandates a larger render. The producer can complete these agreed reversible steps without seeking a fresh parent permission for each file, frame, node or metadata correction; inspect unknown submission state before recovery. Return content, source-family, model/service or scope drift for a decision, and respect actual tool approvals. Use the existing versioned dependency/receipt records and one consolidated result containing the actual file, relevant technical findings, source/job binding and uncovered review scope. Consume that completed result instead of asking the producer and parent to rediscover the same successful state through repeated status, probe or hash readbacks; refresh changed/failed/unknown state and retain required live checks. Do not multiply custom ledgers or demand that the parent manually reread the same source tree at every stage.
4. **Hook first.** For complete feed films the first rendered deliverable is the [hook sample](viral-appeal-and-packaging.md#produce-and-test-the-hook-first): the animator/visual artist own the hook shot at final quality, the audio editor sets the hard start (first syllable by the policy onset, frame-0 caption and event sound, no fades), the producer renders it, runs `scripts/opening_hook.py measure` and writes the local phone-feed previews, and a fresh `video_reviewer` with no script or package context performs the cold two-second test. A failed test returns to the parent's hook lab (picture, pattern or line) before more of the film is refined; G3 cannot approve expansion without the passed sample record.
5. After an output exists, assign the required review to a fresh context. At G2 and G5, the expression reviewer also performs the cold-view [scroll-viewer appeal check](viral-appeal-and-packaging.md#scroll-viewer-appeal-check) before reading the author's rationale, returning frame-0/1 s/2 s hook judgments, swipe-risk times and promise-to-payoff gaps. At G5, use separate `video_reviewer` instances for explanation and expression as required by [quality acceptance](quality-acceptance.md#autonomous-explanation-and-expression-review); the author or producer cannot supply their own independent pass. The parent integrates findings, sends bounded fixes to the responsible author, and requests rechecks of the affected context.

Start only the roles with useful work now, within the host's actual available slots; two or three independent tasks are often enough, and a small repair may need only one author. Role count, model concurrency and CPU/GPU job concurrency are different. Give the author a complete affected interval and the producer one bundled execution request; do not make the parent relay each test frame among idle agents. Assign media review when reviewable output exists and request consolidated findings. Use actual task/status events and bounded waits rather than repeated short polls or status-only follow-ups. If a forecast is missed, the diagnostic allowance is exhausted or the same defect family recurs without playable progress, the child stops diagnostics under that decision and returns one cause/cost packet. The parent must apply the [recovery decision](blender-execution.md#complete-a-repair-cycle-before-expanding), select a changed method and continue feasible authorized work; it cannot treat a child's allowance exhaustion as completion or a permanent stop of the commission. Once applicable mechanism/appearance preflight is covered and the affected continuous sequence is available, the producer/editor assembles its playable candidate directly, omitting intermediate encodes without a distinct purpose, before another cosmetic lookdev round; the parent verifies the actual file, not a promise or preflight receipt. This is a handoff in the existing queue, not a new approval stage. Reuse agents for fixes, and continue independent authorized work while dependencies run. The parent propagates steering/cancellation, checks actual job status before recovery, and retains stage/expansion decisions.

## Independent review

Use two phases in the same review assignment. First provide only the intended audience, assigned responsibility, media/version and allowed viewing scope, actual capability limits, and any safety-critical viewing warning. Show a title/cover only if it is actually part of the commissioned encounter, recording that context. Do not disclose the intended answer, episode-question wording absent from the media, package rationale, author self-review, predicted dropout times, or desired diagnosis before the reviewer records its first-view account and time-coded findings. Then provide the brief, fact cards, intended question/payoff and relevant references for comparison and diagnosis. If the reviewer has already seen those materials or the production history, call its findings informed review rather than cold-view evidence; use a fresh context for a genuinely needed first-view check, not a fabricated reset. Use a fresh agent without production history when the host supports that separation. A fresh subagent is not a human audience test.

Require the reviewer to state whether it can actually inspect images, perceive continuous video and listen to audio. A checker, transcript, contact sheet or successful playback command does not prove normal-speed audiovisual viewing. Missing capability remains unreviewed and returns to the parent for an appropriate review route. Use the existing QA records and failure handling; role completion is not G3/G5 approval.

## Installation and invocation

The TOML files in this Skill's `agents/` directory are maintained custom-agent definitions, not separate Skills or `agents/openai.yaml` UI metadata. Codex discovers personal custom agents under `${CODEX_HOME}/agents`, or `~/.codex/agents` when unset. Keep one global Skill and sync only these six definitions to that personal agent directory. No project-specific Skill or agent installation is needed.

From the installed global Skill, with an existing Python 3.11+ interpreter:

```powershell
$skillRoot = '<absolute global Skill directory>'
python -X utf8 "$skillRoot/scripts/sync_video_agents.py" --check
python -X utf8 "$skillRoot/scripts/sync_video_agents.py" --install
```

`--check` is read-only and checks definition files only; success does not prove host discovery, role invocation or production quality. If named installed definitions differ, inspect the differences before deliberately updating them with `--install --replace-existing`. Replacements keep hash-named `.bak` copies; unrelated agents and `config.toml` are untouched. `--codex-home` can select an actual non-default Codex home. This helper installs only agent definitions, not the Skill, models, plugins or services.

After installation, distinguish three actual states: definition files match; the host exposes the role; an agent has been invoked for a bounded task. Inspect the current tool schema before selecting `agent_type`. If the custom role is unavailable, use an available `worker`/`default` with that definition's instructions and the same assignment now, explicitly recording the intended role and actual fallback. Do not wait for a client refresh to do work that this fallback can perform. A new/reloaded client session may discover the custom names; verify the exposed list before claiming native availability. Do not restart an active production session or launch all six roles merely to test discovery.

On first assignment or a changed role version, the child acknowledges the intended role, native/fallback agent type, definition path/hash it actually read, owned output and current scope in its ordinary first update. This compact acknowledgement is not a new approval gate or per-frame form. The parent records the real task identifier and resulting artifact in the existing work log; reused older agents must read the current definition before being described as fulfilling that role. A successful configuration sync or a renamed task alone cannot establish role execution. Do not claim a model or perception capability the host has not actually supplied.

Natural-language invocation examples:

> Use the global science-video-production Skill. Coordinate the needed video subagents to make this manufacturing explanation. Start with video_researcher and video_visual_artist on separate outputs, then assign motion and audio work. Let video_producer_windows run the agreed local jobs and use fresh video_reviewer contexts for the required reviews.

> Fix only this shot's grasp/contact animation. Assign video_animator the animation module, keep the approved geometry and voice, then have video_producer_windows render the affected sample and video_reviewer inspect contact and timing.

When the host exposes `collaboration.spawn_agent`, the parent supplies `agent_type` using a listed role name, a unique `task_name`, and `message` containing the assignment above. For an independent review use `fork_turns="none"`; explicitly include the global Skill path and review inputs. Use `send_message` for steering a running agent, `followup_task` for continued work, and the available wait/status tools to collect results. Tool names and accepted arguments must follow the current host, not a copied invocation example. Users need only state the desired delegation in ordinary language.

These definitions omit model and reasoning overrides so the host's current defaults apply. They do not alter global concurrency or permission settings. See the [official custom-agent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents) for the client format and configuration semantics.

## Accept handoffs by meaning, not only by file presence

Keep handoffs in the existing assignment/result, with one authoritative artifact/version and its actual state. Research hands off supported claims, conditions and unresolved competing explanations; visual/motion authors hand off the demonstrated relation and known gaps; audio/editing hands off the actual timing, preserved qualifiers and affected joins; execution returns actual output and status, not content approval. The receiving role checks the specific dependency it will use, not the entire project again.

When a shared claim, timing or object interface changes, identify downstream consumers and affected checks before they continue from stale inputs. A received file or technically successful render does not accept its scientific meaning or viewing quality. Return a concrete discrepancy to its owner; the parent resolves cross-role conflicts in one repair decision, preserving valid unrelated work. Separate an observed requirement from a suggested remedy: a shorter-pause request must not erase necessary observation time. Revise the line or staging when that preserves both valid findings; do not automatically accelerate speech, and do not let aesthetic preference override an unresolved scientific contradiction. Do not have the producer silently rewrite another role's in-use source to make a gate pass.

For G5 independent responsibilities, record the actual reviewer/task identity in the existing reviewer/work-log fields, not just the shared role name `video_reviewer`. The same model type is allowed; two task labels on one generation-contaminated context do not establish independence. Duplicate declared identities or reused first-view observations cannot establish two independent passes. Tool validation only checks declared consistency; the parent must verify actual context and perception.
