# 渲染边界与取证副本

本页是 [质量验收](quality-acceptance.md#记录与技术检查) 的小型操作参考，不创建新的阶段、统一帧数/尺寸阈值或通过结论。数值检查、像素取证、正常速度连续观看和真实设备观察分别记录；仅整理Skill不改生产媒体。

## 透明度：最后赋值前检查

[Canvas标准](https://html.spec.whatwg.org/multipage/canvas.html#dom-context-2d-globalalpha) 规定：NaN、无穷和超出0–1的globalAlpha赋值会被忽略，原状态保留。理论上已落在0–1的缓动式，浮点运算仍可能越界；只夹紧输入进度不足以保证最终透明度合法。

在实际渲染入口对最终透明度做有限值检查，再夹紧。不要依靠Canvas自动修正，也不要把非有限值悄悄变成0：应定位计算错误，阻断该次渲染或使用项目明确记录的处理。示意实现：

    function checkedAlpha(value) {
      if (typeof value !== 'number' || !Number.isFinite(value)) {
        throw new Error('non-finite alpha');
      }
      return Math.max(0, Math.min(1, value));
    }
    context.globalAlpha = checkedAlpha(finalAlpha);

`scripts/render_evidence_checks.py` 的 `clamp_alpha` 是同一边界的Python参考与回归入口，不会自动修改或接入任何生产Canvas渲染器。实际采用须核生产最后一次赋值、层叠状态及当前渲染入口，并用该入口重跑。

对实际淡入/淡出区间，按当前帧时轴、缓动与合成风险检查端点、浮点邻值和邻近采样；检查最终alpha均为有限0–1。保留原异常和处理结果，不能只测试理想端点。邻近帧范围由实际故障/变化确定，不固定帧数；再从当前编码导出核相关密序帧和连续片段，防止旧alpha残留、闪现或错误图层仍可见。参考函数通过不证明当前成片已修复。

## 平移：分别核四边

只有完整不透明、无裁剪/遮罩、无旋转/斜切、正缩放后的轴对齐矩形，才可直接用以下几何条件。画布尺寸为W、H，最终绘制矩形尺寸为Dw、Dh，最终左上坐标为tx、ty：

- 左、上：tx ≤ 0，ty ≤ 0
- 右、下：tx + Dw ≥ W，ty + Dh ≥ H
- 可行平移范围：W − Dw ≤ tx ≤ 0，H − Dh ≤ ty ≤ 0；Dw < W或Dh < H时，仅平移无法全覆盖

使用已合并实际锚点、缩放及变换顺序的画布坐标，不把源图尺寸直接当绘制尺寸。`axis_aligned_coverage(W, H, Dw, Dh, tx, ty)`返回四边分别结果、全覆盖结果与可行范围；它不改镜头，也不判断素材真的满足前提。逐帧轨迹与所有四边极值均需核，不能只测中心或起终点。

旋转、遮罩、透明边缘、非矩形素材和实际抗锯齿覆盖须检查变换后的实际像素/alpha，不能借外包矩形公式宣称全画布覆盖。无论公式是否通过，都在最终编码检查镜头极值和接点；黑边也可能来自素材本身。没有暴露底色不等于画面美术通过，不能用模糊或贴色掩盖真实缺边。

## 从现有抽帧生成目标尺寸PNG

优先复用 [现有抽帧工具](shotbook.md#整片视觉抽帧工具)。`build_visual_review.py` 已从指定编码媒体按实际解码帧号抽取原尺寸PNG，并绑定媒体SHA、帧号和时间；它的start/mid/end样本不自动覆盖全部运动极值、透明度风险或中间瞬态。

需要目标观看尺寸的审查图时，先确认源文件就是本次实际审查的最终编码版本，并用既有命令生成新目录：

    python scripts/build_visual_review.py path/to/episode.json --media final.mp4 --output review-new

保留并核该次 `review-new/manifest.json` 的SHA-256、媒体SHA、实际帧号/时间及原PNG哈希。在当前项目既有的受控取证流程中，将对应原尺寸PNG按实际观看尺寸等比缩放，并仍保存PNG；可用已装FFmpeg或Pillow，不另加文件派生工具。记录实际目标宽高、像素取整方法、工具/版本、缩放滤波、输出格式和PNG哈希，并保留到原帧的身份链。不能仅改扩展名，也不能拿渲染源截图代替最终编码帧。

目标尺寸按本次实际观看场景选择，没有通用“手机合格”宽度。需要不同画幅应单独设计/审查，不把拉伸或裁切证据当作同一画面。输入/输出使用已经核对的本地项目路径，保留源证据并另存新结果；确认无并发移动/替换，沿既有工具的输出保护执行，不声称这些工具提供任意并发文件系统下的安全事务。当前新增模块仅含alpha/四边纯函数，没有文件读写或PNG派生命令。

PNG无损只指目标尺寸像素的保存不再引入JPEG压缩损失；缩放本身改变像素，原视频压缩损失不会恢复。普通PNG缩放也不提供HDR色调映射、屏幕色彩管理或真实手机播放模拟。若审查链必须使用JPEG，明确质量设置，并以同帧、同尺寸无损PNG对照，区分截图新增伪影与成片本身问题。PNG用于此处取证，不是对视频交付格式的限制。

## 回归与结论范围

    python -m unittest discover -s scripts/tests -p 'test_render_evidence_checks.py' -v

- 数值回归：有限输入、端点及浮点邻值、五次缓动越界、非法输入、四边极值、逐边缺口、不能覆盖的尺寸与溢出
- 可选已装Canvas运行时：真实绘制负alpha保留旧状态与夹紧后像素、四个平移极值全覆盖，以及旋转后外包框覆盖但实际角落空缺的合成反例；缺运行时标skip，不下载。它不是所有浏览器的兼容性认证
- 已装FFmpeg/Pillow的合成编码回归：原工具抽帧与当前编码帧逐像素一致，帧号/时间/媒体身份可核；测试内目标尺寸PNG与缩放结果逐像素一致，JPEG合成对照确会改变这些像素。另核既有抽帧器拒绝已有输出和越界媒体路径；不宣称覆盖所有并发路径竞争

合成测试不证明当前生产入口已采用修正、真实素材覆盖、观众可读性、正常速度主体动态、声音、审美或任何实机通过。测试使用的尺寸、帧数、JPEG质量仅为合成夹具，不作未来视频阈值。
